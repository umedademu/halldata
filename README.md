パチスロ店のデータを収集するアプリ

現在の叩き台版では、`apps/gui` の画面から MJアリーナ箱崎店 の対象日データを取得できます。
先に登録店舗から対象店舗を選び、対象期間を入力し、期間の終了日を基準に機種一覧を読み込み、チェックした機種をまとめて取得する流れです。
機種一覧の読込直後は全機種が選択済みになり、取得完了時は初期状態で音を鳴らします。
また、`登録店舗` タブでURLから店舗名を自動取得して登録でき、登録店舗一覧はローカル設定として保存し、R2上のWeb表示用索引でも不足分を補います。
店舗URLは保存前に表記ゆれをそろえて扱うため、同じ店舗URLで重複した店舗行が増えにくいようにしています。
GUIアプリでは取得状況と保存結果だけを表示し、詳細な台データや分析はWebアプリで確認します。
取得中は、機種ごとのデータ取得が終わるたびにローカルへ一時退避し、指定した日数分または店舗分の取得後に Cloudflare R2 へ自動保存します。R2保存とWeb表示用JSON更新が成功した日付分のローカル退避は削除し、失敗時は復旧用に残します。
保存時は、Webアプリが読むための表示用JSONもR2上で更新します。表示用JSONは店舗概要と機種別データに分けて保存します。
取得に失敗した場合は、画面で指定した秒数だけ休止してから最大3回まで再試行します。初期値は10秒です。
再取得時は、すでに保存済みの同一店舗、同一日付、同一機種の組み合わせをR2から確認し、取得をスキップします。
また、`登録店舗` タブには `サイトセブン` `推定差枚` `都道府県` `地域` `SS店舗名` `SS ID` `SS住所` の列があり、サイトセブン列にチェックを入れた店舗だけを `データ取得` タブの `サイトセブン取得` でまとめて取得できます。
`推定差枚` 列にチェックを入れた店舗は、`データ取得` タブの `推定差枚ページを開く` で、スマホ版サイトセブンの機種別ページから `出玉推移グラフ` を経由し、台番ごとの出玉推移グラフページまでブラウザで移動できます。現時点ではページ表示までで、グラフから差枚を読み取って保存する処理はまだ行いません。
`都道府県` の初期値は `福岡県`、`SS店舗名` の初期値は登録した店舗名です。`SS ID` は地区一覧にある `hallClick` の値、`SS住所` は補助の照合情報として使います。必要なら一覧から店舗を選んで入力欄へ読み戻し、手動で更新できます。
サイトセブンは初回だけ専用のログイン画面をブラウザで開き、ログイン後ページや対象店舗ページを確認できた時点で、その状態を `local_data` 配下へ保存して次回起動時以降も使い回します。
サイトセブンのデータ取得時に使うブラウザは、画面上で `表示` と `非表示` を切り替えられ、初期値は `表示` です。なお、ログイン操作そのものは毎回ブラウザを表示して開きます。
`表示` で取得した場合も、取得完了後は操作に使ったブラウザを閉じます。続けて `サイトセブン取得` を押した場合は、保存済みログイン情報を使って新しいブラウザを開き、`Top.do` から取得し直します。
サイトセブン取得では、店舗ページへ直接飛ばずに `Top.do` から、登録店舗ごとに入力された `都道府県` `地域` を使って地区ページと店舗ページを辿ってから対象機種ページへ進みます。
地区ページでは、まず `SS ID`、次に `SS住所`、最後に `SS店舗名` の順で店舗を選びます。
既知の店舗名に当てはまる場合は、`SS店舗名` が半角寄りでも内部で `SS ID` や住所などの補助情報を補って照合します。
`SS店舗名`、`SS住所`、地区リンクの照合では、全角と半角、空白、ハイフン、記号、末尾の `店` などの揺れをある程度吸収して比較します。
サイトセブン内のページ移動の間には、毎回 2 秒から 4 秒のゆらぎ待ちを入れています。
サイトセブン欄には専用の `中止` ボタンもあり、取得中はその場から停止を指示できます。ページ遷移の合間やゆらぎ待機中は、そのまま停止できます。
サイトセブン欄の `定期取得` では、10時から23時のチェックした時刻に、各時刻1日1回だけ取得します。初期値は12時、15時、18時、21時です。
サイトセブン取得では、保存前に既存の `Aパーク春日店` と `GOGOアリーナ天神` を優先して寄せ先を決め、別店舗として増やさないようにしています。
保存の優先順位は `みんレポ` が上です。サイトセブンは、みんレポの同じ日付と機種がまだ無い場合だけ仮置きし、すでにみんレポ由来のデータがある日付と機種には上書きしません。
同じ日付と機種にサイトセブン由来の仮置きが残っている場合だけ、サイトセブン取得で入れ直します。あとからみんレポを取得した場合は、その内容で上書きされます。
サイトセブンや既存保存データで機種名の表記ゆれがある場合も、保存時に設定ファイルの基準名へ寄せて扱います。ただし `ネオアイムジャグラーEX` と `SアイムジャグラーＥＸ` は別機種として分けています。
サイトセブン取得では、差枚計算条件がある機種は `差枚` を自動計算し、四捨五入した整数として `累計ゲーム`、`BB回数`、`RB回数`、`合成確率`、`BB確率`、`RB確率` とあわせて既存と同じ保存形式へ並べます。`出率` は引き続き空欄です。
サイトセブン対象機種と差枚計算条件は `config/machine_difference_rules.json` に置いてあり、今は `ネオアイムジャグラーEX`、`SアイムジャグラーＥＸ`、`マイジャグラー`、`ゴーゴージャグラー`、`ファンキージャグラー`、`ミスタージャグラー`、`ジャグラーガールズ`、`ウルトラミラクルジャグラー`、`ハッピージャグラー`、`ニューキングハナハナ`、`キングハナハナ`、`ハナハナホウオウ`、`スマスロ ハナビ`、`新ハナビ`、`スターハナハナ`、`ドラゴンハナハナ～閃光～` に対応しています。
サイトセブンの対象機種判定は完全一致だけでなく、設定ファイルに置いた対象語を含むかどうかでも見ます。今後はこの設定へ機種名や対象語を足すだけで同じ仕組みを使い回せます。
サイトセブン取得でも、対象機種ごとの取得が終わるたびにR2へ自動保存します。
サイトセブン取得で過去日の同一機種データがすでにR2にある場合は、その日付を保存前にスキップします。
サイトセブン側で取れる日数は直近8日までです。
新しく環境を作る場合は、`apps/gui/requirements.txt` の導入後に `python -m playwright install chromium` も一度実行してください。
R2保存には、`.env.local` の `CLOUDFLARE_ACCOUNT_ID`、`CLOUDFLARE_R2_BUCKET_NAME`、`CLOUDFLARE_R2_ACCESS_KEY_ID`、`CLOUDFLARE_R2_SECRET_ACCESS_KEY`、`CLOUDFLARE_R2_ENDPOINT` を使います。
`apps/web` には、保存された内容を `店舗一覧 → 機種一覧 → 台データ` の順で見られるサイトを用意しています。
WebサイトはR2の公開URLにある表示用JSONだけを読みます。機種ページでは必要な機種のJSONだけを読みます。
Web表示には `CLOUDFLARE_R2_PUBLIC_BASE_URL` も必要です。
既存のCSVから表示用JSONをR2へ作る場合は、`python apps/gui/web_data_export.py --source csv` を実行します。
既存の `apps/web/public/halldata-static` からR2へ移す場合は、`python apps/gui/migrate_static_web_data_to_r2.py` を実行します。
機種一覧ページは店舗全体の最新日一日分ではなく、各機種ごとの最新記録日を基準に一覧を出します。
Web側も、設定ファイルで同じ機種として扱う表記ゆれは一つの機種としてまとめて表示します。
このサイトは `PC` と `スマホ` の両方で、台データを横長の比較表として見られます。
