# ジャグラー推定ブドウ計算メモ

このメモは、アイム系、ゴーゴージャグラー、ファンキージャグラー、ジャグラーガールズ、マイジャグラー、ミスタージャグラーの「推定ブドウ」を今後ほかのジャグラー系へ広げるときに、同じ考え方で実装できるように残すものです。

## 結論

- 推定ブドウは、みんレポ由来の `差枚`、`G数`、`BB`、`RB` から逆算した通常時3枚がけのブドウ推定値です。
- 実測のブドウ回数ではありません。
- 1枚がけ中に成立したブドウは、払い出しには反映しますが、通常時ブドウ回数には含めません。
- みんレポのG数は、1枚がけ周りの扱いが店表示機や実測値と完全には一致しない前提で、1枚がけ想定回数に機種別の補正係数を掛けた分だけ内部計算上の通常時G数から引きます。
- 補正係数は理論値ではなく、実測値や長期平均とのズレを見て採用した暫定係数です。変更する場合は保存済みデータの再計算と版の更新が必要です。

## 対象機種

現在の対象は次の6系統です。

| 系統 | 判定 | BIG枚数 | REG枚数 | 後告知比率 |
| --- | --- | ---: | ---: | ---: |
| アイム系 | `アイムジャグラーEX` を含む機種名 | 252 | 96 | 0.75 |
| ゴーゴージャグラー | `ゴーゴージャグラー` を含む機種名 | 240 | 96 | 1.00 |
| ファンキージャグラー | `ファンキージャグラー2` を含む機種名 | 240 | 96 | 0.75 |
| ジャグラーガールズ | `ジャグラーガールズ` を含む機種名 | 240 | 96 | 0.75 |
| マイジャグラー | `マイジャグラー` を含む機種名 | 240 | 96 | 0.75 |
| ミスタージャグラー | `ミスタージャグラー` を含む機種名 | 240 | 96 | 0.75 |

## 計算の流れ

入力値は、みんレポ由来の `差枚`、`G数`、`BB`、`RB` です。

1. `ボーナス回数 = BB + RB`
2. `後告知ボーナス回数 = ボーナス回数 * 後告知比率`
3. `1枚がけ終了確率 = 1 - 1/10.3 - 1/7.3`
4. `1枚がけ想定回数 = 後告知ボーナス回数 / 1枚がけ終了確率`
5. `みんレポG数補正 = 1枚がけ想定回数 * 機種別補正係数`
6. `通常時G数 = みんレポG数 - みんレポG数補正`
7. `差枚補正 = みんレポ差枚 - 後告知ボーナス回数 / 7.30`
8. `投入枚数 = 通常時G数 * 3 + 1枚がけ想定回数`
9. `ボーナス払い出し = BB * BIG枚数 + RB * REG枚数`
10. `小役払い出し合計 = 差枚補正 + 投入枚数 - ボーナス払い出し`
11. `通常時リプレイ払い出し = 通常時G数 * 3 / 7.30`
12. `通常時チェリー払い出し = 通常時G数 * チェリー枚数 * チェリー確率 * チェリー取得率`
13. `通常時の追加小役払い出し = 通常時G数 * 追加小役確率 * 追加小役枚数 * 追加小役取得率`
14. `1枚がけブドウ払い出し = 1枚がけ想定回数 * 8 / 10.3`
15. `1枚がけリプレイ払い出し = 1枚がけ想定回数 * 1 / 7.3`
16. `通常時ブドウ払い出し = 小役払い出し合計 - 通常時リプレイ払い出し - 通常時チェリー払い出し - 通常時の追加小役払い出し - 1枚がけブドウ払い出し - 1枚がけリプレイ払い出し`
17. `推定ブドウ回数 = 通常時ブドウ払い出し / 8`
18. `推定ブドウ分母 = 通常時G数 / 推定ブドウ回数`
19. `推定ブドウ確率 = 推定ブドウ回数 / 通常時G数`

画面上の `ブドウ` 列には、`推定ブドウ分母` だけを `6.13` のように表示します。

## G数補正の考え方

1枚がけ回数をそのまま全てG数から引くと、実測カウントとズレやすくなります。  
一方で、1枚がけを完全に無視すると、みんレポG数に含まれていると考えられる1枚がけ由来のズレを放置することになります。

そのため現在は、店表示機寄せと実測カウント寄せの中間を取る目的で、`1枚がけ想定回数 * 機種別補正係数` をみんレポG数から引いています。

アイム系は、長期平均の推定ブドウが設定1の小役前提より重く出やすかったため、係数を `0.30` に下げています。ゴーゴージャグラー、マイジャグラー、ミスタージャグラーは、現時点では `0.725` のままです。ファンキージャグラーは、Aパーク春日店の1年分CSVを合算した平均が `5.97` 付近になるよう、係数を `1.443` にしています。ジャグラーガールズは、同店の1年分CSVを合算した平均が `5.99` 付近になるよう、係数を `-1.013` にしています。

この係数は物理的な確定仕様ではありません。  
今後、より多くの実測データで違う係数の方が安定すると判断した場合は、係数を変更し、保存済みデータを再計算します。

## 差枚補正の考え方

みんレポ差枚と実差枚を比較したとき、後告知比率が高い機種ほど、1枚がけ周りの差枚ズレが出やすい可能性がありました。

現在は、その補正として `後告知ボーナス回数 / 7.30` 枚をみんレポ差枚から引きます。

この補正も確定仕様ではなく、1枚がけ時リプレイや信号処理のズレを中間的に吸収するための暫定補正です。

## 推定設定との関係

ブドウ加味推定設定は、次の順で出します。

1. まず `BB` と `RB` だけで仮の推定設定を出す
2. その仮設定を使って、チェリー確率を補間する
3. 差枚、G数、BB、RB、チェリー確率から推定ブドウを逆算する
4. `BB`、`RB`、推定ブドウを使って最終的なブドウ加味推定設定を出す

保存済みの `estimated_grape_count`、`estimated_grape_denominator`、`estimated_grape_probability` がある場合は、表示時に毎回逆算せず、その保存値を使います。

## 保存値の版

現在の版は次の通りです。

| 保存値 | 版 |
| --- | ---: |
| 推定ブドウ | 5 |
| ブドウ加味推定設定 | 4 |

補正係数、小役確率、払い出し、対象機種、計算順序を変えた場合は、原則として版を上げます。  
版を上げた場合は、既存R2データの再計算も必要です。

## 実装箇所

- GUI取得時の推定ブドウ計算: `apps/gui/estimated_grape.py`
- GUI取得時のブドウ加味推定設定: `apps/gui/setting_estimates.py`
- Web表示時の再計算 fallback: `apps/web/lib/setting-estimates.js`
- 設定別ボーナス、ブドウ、チェリー、機械割: `config/setting_estimates.json`

通常運用では、取得時または一括更新時に保存済みの値を作り、Web表示では保存値を優先します。

## ほかのジャグラー系へ広げるときの作業

新しいジャグラー系へ広げる場合は、最低限次の情報を決めます。

1. 機種名の判定語
2. BIG枚数
3. REG枚数
4. 後告知比率
5. 設定別ブドウ確率
6. 設定別チェリー確率
7. 設定別BB確率
8. 設定別RB確率
9. 設定別機械割

実装時は、Python側とWeb側の対象機種定義を両方更新します。  
既存データがある場合は、一括更新で `推定ブドウ` と `ブドウ加味推定設定` を再計算します。

## 注意点

- 推定ブドウは、みんレポ差枚からの逆算値なので、個人の実測カウントと完全一致するものではありません。
- 打ち手の小役フォローミス、カウントミス、実際のリプレイやチェリーの上振れ下振れで差が出ます。
- 機種別G数補正係数や差枚補正は、現時点で一番辻褄が良いと判断した暫定補正です。
- 今後データが増えたら、係数を再検証する余地があります。
