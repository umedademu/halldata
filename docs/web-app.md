# Webサイトの現状

## 画面構成

- `apps/web` に `Vercel` 向けのサイトを用意しています
- ページの流れは `店舗一覧 → 機種一覧 → 台データ` です
- 全店舗の店舗ページ上部には、`狙い度ランキング` と `バックテスト` への導線があります
- 店舗一覧の上部には、複数店舗を同じ条件で比べる `店舗横断バックテスト` への導線があります
- 全画面の上部には、`店舗選択`、`店舗横断バックテスト`、`更新情報` の切り替えボタンを表示します
- `更新情報` のURLは `/updates` です
- 全店舗の店舗ページ上部、機種別ページ上部、狙い度ランキングページ上部、バックテストページ上部では、その店舗に適用する狙い度ロジックを切り替えられます。ロジック名と計算内容の作成・編集は開発環境側だけで行い、Webアプリでは店舗ごとの適用先だけを保存します
- 狙い度ロジックの初期値は、`ミリオン東武練馬店スロット館` は `ミリオン東武練馬式`、`アミューズ浅草店` は `アミューズ浅草式`、`GOGOアリーナ天神` は `GOGO式`、`玉屋409雑餉隈` は `玉屋雑餉隈式`、`玉屋555大橋店` は `玉屋555大橋店式`、`HINODE大野城店` は `HINODE大野城式`、`123博多店` は `123博多式`、`BOOM天神店` は `BOOM天神式`、`ビームヒカリ店` は `ビームヒカリ式A`、`MJアリーナ井尻店` は `MJアリーナ井尻式A`、`MJアリーナ空港店` は `MJアリーナ空港式A`、`スロットまるみつ大橋店` は `スロットまるみつ大橋式A`、`ワンダーランド南ヶ丘店` は `ワンダーランド南ヶ丘式B`、`ワンダーランド須恵店` は `ワンダーランド須恵式A`、`A-PARK屋形原` は `Aパーク屋形原式A`、その他の店舗は `Aパーク春日式` です
- ブラウザーのタブ名は固定ではなく、`店舗一覧`、各店舗の `機種一覧`、`狙い度ランキング`、`バックテスト`、各機種の `台データ` に応じて切り替わります
- `店舗一覧` では、保存済みの店舗名を検索して絞り込めます
- `店舗一覧` では、店舗一覧枠の上に `マイホール` 枠を表示し、店舗ごとの星を押すことでお気に入り店舗を登録・解除できます
- `店舗横断バックテスト` の結果表、店舗ページ、狙い度ランキング、バックテスト、台データの上部でも、店舗名の近くにある星から同じお気に入り登録・解除ができます
- `マイホール` に登録した店舗は、ドラッグで自由に並び替えできます
- `マイホール` の保存先はブラウザー側の端末保存で、保存キーは `halldata-my-hall-store-ids` です
- `店舗一覧` では、保存済み店舗を都道府県ごと、さらに地域ごとに分けて表示します
- `店舗一覧` では、都道府県内の地域を広い画面で4列、画面幅に応じて3列、2列、1列へ切り替えて表示します
- `店舗一覧` の地域ごとの一覧は折りたたみ式で、初期表示では閉じています
- `店舗一覧` の地域ごとの一覧は、展開しても地域ブロックの並び順と位置が入れ替わらないように表示します
- 店舗名で検索した時は、該当店舗が見えるように地域ごとの一覧を開いた状態で表示します
- 登録済みでも台データが未取得の店舗は一覧に表示し、店舗ページでは未取得案内を出します
- みんレポ上の都道府県単位の店舗一覧を元に、店舗追加や登録情報補完を先に行い、台データ未取得の店舗ページだけ先に公開する運用もできます
- 店舗の追加や編集はGUIアプリで行い、Web側では登録操作を行いません
- `機種一覧` の上部には店舗名、元ページへのリンク、`狙い度ランキング` と `バックテスト` へのリンク、狙い度ロジックの切替を表示します
- `機種一覧` では、表の上に追加の見出しを置かず、すぐ機種表を表示します
- `機種一覧` では、各機種ごとの最新記録日を基準に、保存済みの機種をリンク付きの表で見られます
- `台データ` の上部には機種名、店舗名、機種一覧へ戻るリンク、店舗ページを開くリンク、狙い度ロジックの切替を表示します
- `台データ` では、同じ台番のデータを日付ごとに比較できます
- `台データ` の設定推測用スペック表は、初期状態では閉じた折りたたみ表示にしています
- トップページ、店舗ページ、狙い度ランキングページ、バックテストページ、機種ページの上部見出しは、トップページの `保存済み店舗` と同程度の文字サイズで表示します
- 各ページの上部では、表示元の表記を出さず、画面の目的と操作導線を優先します

## データの読み出し

- Web表示では、Cloudflare R2 の公開URLにある表示用JSONだけを読みます
- Web表示用JSONの店舗索引には、GUIアプリの登録店舗で保存した都道府県と地域も含めます
- Web表示用JSONの店舗索引と店舗概要には、GUIアプリがみんレポの `旧イベント日` から取得した特定日条件も含めます。条件は日付末尾、毎月の日付、ゾロ目、曜日に分けて保存します
- 店舗概要JSONの都道府県や地域が古い場合でも、店舗索引にある登録済みの都道府県と地域を優先して表示に使います
- 店舗一覧、機種一覧、台データ、狙い度ランキング、バックテストはR2上の表示用JSONだけを読んで表示します
- 表示用JSONは店舗概要と機種別データに分けて保存し、機種ページでは必要な機種のJSONだけを読みます
- 狙い度ランキングとバックテストは、初回表示では店舗概要JSONだけを読み、結果表示時にチェックした対象機種のJSONを同時に読み込みます
- 表示用JSONが無い環境では、WebアプリはSupabaseやgit上のJSONへ戻らず、データなしとして扱います
- R2の公開URLは `CLOUDFLARE_R2_PUBLIC_BASE_URL` に設定します。`r2.dev` の公開URLか、R2に割り当てた独自ドメインを入れます
- ローカル確認時は、ルートの `.env.local` も読めるようにしています
- 本番の `Vercel` では、同じ環境変数を `Vercel` 側に設定する想定です
- 既存のCSV退避データは、`stores_rows.csv` と `machine_daily_results_rows.csv` から `python apps/gui/web_data_export.py --source csv` でR2へ移行できます
- 既存の `apps/web/public/halldata-static` は `python apps/gui/migrate_static_web_data_to_r2.py` でR2へ移行できます

## 表示について

- 画面全体は白と薄い灰色を基調にし、装飾を抑えた表示にしています
- `PC` と `スマホ` の両方で、左端の日付列を固定した横長の比較表で見られます
- `スマホ` では店舗一覧、機種一覧、台データ比較の表を横に動かしながら確認します
- 店舗一覧は表示用JSONの索引だけを読み、台データ行は読みません
- 機種一覧は、表示用JSONにある機種要約を優先して表示します
- 表示用JSONが使えない環境では、機種一覧や台データは表示できません
- 機種一覧の台数、平均差枚、平均G数、平均出率は、それぞれの機種にとって最新の日一日分をもとに表示します
- 機種一覧は、ジャグ系を先頭にまとめ、その中では台数が多い順で表示します。アイム系やハナビ系の統合行は親行と子行をまとまりとして表示します。ジャグ系以外は従来どおり、機種ごとの最新日が新しい順、その次に台数の多い順で表示します
- `ゴーゴージャグラー3` と `ゴーゴージャグラー３` のような機種名の表記ゆれは、設定ファイルをもとに同じ機種としてまとめて表示します
- `ネオアイムジャグラーEX` と `SアイムジャグラーＥＸ` は、片方だけが現行機種一覧にある店舗でも、機種一覧に統合ページの `アイムジャグラーEX` を出します。旧機種と新機種が入れ替わった店舗では、台数や平均値は最新日の機種側を使い、過去データは統合ページでまとめて見られます
- `新ハナビ` と `スマスロ ハナビ` が両方ある店舗では、機種一覧に統合ページの `ハナビ` を出し、その下に個別ページの2機種をインデントして表示します
- 差枚計算条件がある機種では `G数`、`BB`、`RB` から `ボーナス数基準差枚` を作り、保存済みの差枚とは別に表示用JSONへ持たせます
- 差枚の計算条件と機種名の表記寄せはルートの `config/machine_difference_rules.json` にまとめてあり、今は `ネオアイムジャグラーEX`、`SアイムジャグラーＥＸ`、`マイジャグラー`、`ゴーゴージャグラー`、`ファンキージャグラー`、`ミスタージャグラー`、`ジャグラーガールズ`、`ウルトラミラクルジャグラー`、`ハッピージャグラー`、`ニューキングハナハナ`、`キングハナハナ`、`ハナハナホウオウ`、`スマスロ ハナビ`、`新ハナビ`、`スターハナハナ`、`ドラゴンハナハナ～閃光～` を登録済みです
- この条件ファイルは、Web側では主に機種名の表記寄せに使うため、`apps/web/config/machine_difference_rules.json` にも同梱しています
- Webサイトでは `ボーナス数基準差枚` と `推定設定基準差枚` を表示用JSONから読みます。`推定設定基準` を選んだ場合も、現在の計算基準で保存済みの値があればその値を使い、古い保存値や保存値がない場合だけ表示時に再計算します
- アイム系、ゴーゴージャグラー3、マイジャグラーVの推定設定基準差枚と設定1基準差枚は、ボーナス後の1枚がけを期待値で分離して計算します。アイム系とマイジャグラーVは後告知75%、ゴーゴージャグラー3は後告知100%とし、1枚がけ中のブドウは `1/10.3`、8枚払い出し、リプレイは `1/7.3` とします。推定設定基準差枚では、リプレイ確率 `1/7.30`、ブドウとチェリー確率を実践値ベースにした設定別コイン持ちも使います
- アイム系、ゴーゴージャグラー3、ファンキージャグラー2、ジャグラーガールズ、マイジャグラーV、ミスタージャグラーの機種別ページでは、表示用JSONに保存された `推定ブドウ` を台データ比較の `ブドウ` 列として表示できます。画面上は `6.13` のように分母だけを表示します。これはみんレポ由来の差枚から逆算した値で、実測のブドウ回数ではありません。ミスタージャグラーだけはチェリー4枚、チェリー取得率97%、ベルピエロ取得率を仮推定設定3.5以上なら75%、3.5未満なら約4.6%として別枠で差し引きます。ボーナス後の1枚がけは、アイム系、ファンキージャグラー2、ジャグラーガールズ、マイジャグラーV、ミスタージャグラーが後告知75%、ゴーゴージャグラー3が後告知100%、1枚がけ中のブドウ `1/10.3`、8枚払い出し、リプレイ `1/7.3` を前提に期待値で分離し、アイム系は1枚がけ想定回数の `0.30` 倍、ゴーゴージャグラー3、マイジャグラーV、ミスタージャグラーは `0.725` 倍、ファンキージャグラー2は `1.443` 倍、ジャグラーガールズは `-1.013` 倍をみんレポG数から引き、後告知ボーナス数÷`7.30` 枚をみんレポ差枚から引いてから逆算します。1枚がけ中のブドウは通常時ブドウ回数には含めません。サイトセブン由来の差枚は計算値なので対象外です。`ブドウ確率を加味` の推定設定は、保存済みの `ブドウ加味推定設定` があればその値を優先します。詳細な思想と計算式は `docs/juggler-grape-estimation.md` にまとめています
- ジャグラーガールズのスペック表では、機械割にチェリー狙い時の数値を表示します。設定1から順に `98.09%`、`99.02%`、`101.09%`、`103.42%`、`105.32%`、`108.84%` です
- ミスタージャグラーのスペック表では、`機械割` という列名は使わず、`チェリー狙い` と `フル攻略` の2列を表示します
- 表示用JSONの各台データに `site7` の取得元情報がある場合は `Sセブン暫定` として扱います。取得元情報がない古いデータは、Sセブン導入前のデータとして通常のみんレポ扱いにします
- `Sセブン暫定` でも、台番以外の実績がすべて空の行は店休日扱いとして表示用JSONへ残しません
- 台データ比較では、横幅を抑えるために表内の日付を `YY/MM/DD` 形式で表示し、日付の隣に曜日を表示し、数値の桁区切りを省いています
- 台データ比較の表では、横幅を抑えるために `狙い度` の見出しを `狙度` と表示し、`合成`、`BB率`、`RB率` は `1/111` ではなく `111` のように分母だけを表示します。CSV出力では従来通り `1/111` 形式を残します
- 台データ比較では、その日付の台データに `Sセブン暫定` が含まれる場合、日付セルだけを茶色系にして `Sセブン` を表示します。取得時刻が表示用JSONにある場合は `Sセブン 12:34` のように時刻も常時表示し、ホバー時に年月日つきの取得日時を表示します
- 台データ比較は、表示用JSON内の機種別データを読みます
- `アイムジャグラーEX` や `ハナビ` の統合ページでは、列見出しに `ネオアイム 101番台`、`Sアイム 201番台` のように元機種が分かる名前を付けます
- 台データ比較では、チェックボックスで表示する列を選べます
- 台データ比較の `出率`、`BB率`、`RB率` は初期状態では非表示です
- アイムジャグラーEX系、スマスロ ハナビ、新ハナビ、スマスロ サンダーV、バーサスリヴァイズ、ハナハナホウオウ、ニューキングハナハナ、キングハナハナ、スターハナハナ、ドラゴンハナハナ～閃光～、ファンキージャグラー2、マイジャグラーV、ハッピージャグラーV、ゴーゴージャグラー、ジャグラーガールズ、ウルトラミラクルジャグラー、ミスタージャグラーの台データ比較では、`G数`、`BB`、`RB` から別アプリと同じ計算方法で設定を推測し、`設定` 列に加重平均値を表示します。設定推定基準は `ボーナス確率のみ` と `ブドウ確率を加味` から選べます
- `ブドウ確率を加味` はアイム系、ゴーゴージャグラー3、マイジャグラーVで有効です。表示用JSONに保存済みの `ブドウ加味推定設定` があれば先に使います。保存値がない古いデータでは、まずBB/RBで仮の設定を出し、その仮設定のチェリー確率を使って保存済みまたは逆算したブドウ回数を読み、最後にBB/RB/ブドウの3項目で推定設定を出します。対象外機種やブドウを読めないデータでは `ボーナス確率のみ` と同じ扱いに戻します
- 対応機種の台データ比較では、`データ推測`、`G数による推測`、`特定日6あり` の比重を入力できます
- `狙い度` 列がある対応機種では、`データ推測` の入力欄の下で、順位範囲、狙い度下限、次点差下限、順位の見方、次点差の比較対象、順位と次点差に使う機種、各条件を必須にするかどうかを指定できます。初期値は順位 `1` から `1`、狙い度と次点差は空欄、機種内順位、機種内次点差、順位だけが必須、表示中の機種のみチェック済みです
- 機種別ページでは、狙い度条件を変更してもすぐ表へ反映せず、`狙い度条件を反映` を押した時だけ反映します。機種内順位・機種内次点差以外を使う場合だけ、全体比較用の狙い度データを追加で読み込みます
- 機種別ページの表示期間は、直近指定か範囲指定かも含めてブラウザー側に全店舗、全機種共通で保存し、次に別の店舗や機種を開いた時も同じ値を復元します
- 機種別ページの台データ比較では、表示中の期間に入っている日付だけを対象に、設定推測、ブドウ列の有無、狙い度列の有無、特定日内比較を判定します。直近90日表示なら、表側の処理も90日分を基準にします
- 機種別ページの日付強調条件、差枚列の表示基準、狙い度計算の差枚基準、表示列、設定推定基準、設定推測の比重、狙い度強調条件、表示条件、設定推測、狙い度の開閉状態はブラウザー側に店舗単位で保存し、次回同じ店舗の機種別ページを開いた時に復元します
- 機種別ページでは、差枚列の表示基準、狙い度計算の差枚基準、設定推定基準などを切り替えてもURLを書き換えず、ページ全体の再読み込みもしません。狙い度の再計算が必要な切替では、表示期間と、その計算に必要な過去90日分だけを追加で読みます
- 機種別ページでは、条件に合う `狙度`、`次差` のセルを薄紫の背景と太字で強調します
- 機種別ページの狙い度強調で順位条件を使う場合、同じ狙い度の台は同順位として扱い、同率1位などもまとめて強調します
- 機種別ページの `次差` 列は、選んだ比較対象の中で自分の狙い度から次に低い狙い度を引いた値を表示します。同点の台が複数ある場合は、同じ次点差を表示します
- `G数による推測` は標準で `6000G` から `9000G` までを指数 `1.5` で評価し、指数を大きくすると後半ほど評価が伸びやすくなります
- `特定日6あり` は、店舗ごとに保存している特定日行だけ、その機種の中で最も良い台を高く見る相対評価として使います
- `特定日6あり` の比較に使う元の評価は、`G数による推測` がオフならデータ推測だけ、オンならデータ推測とG数推測を合わせた値です
- 設定推測の比重は、狙い度ランキング対象機種ではページを開いた時点でデータ推測100%、G数による推測と特定日6ありをオフにします
- 対応機種では、該当台番の表示中の列にポインターを合わせると各設定の推測割合を確認できます
- 対応機種では、推測値が3.5以上は青系、4.0以上は黄色系、4.5以上は緑系、5.0以上は赤系の単色背景と太字で、該当日の該当台番にある表示中の列を強調します
- 日付末尾やゾロ目による行の強調と設定推測による強調が重なった場合は、設定推測による強調を優先します
- `狙い度` は店舗のラインナップにある狙い度対応機種と、その店舗で保存した点数式を読んで計算します

- 台データ比較の表は、「CSV出力」ボタンで表示中の列をCSVファイルとしてダウンロードできます
- 台データ比較のCSVファイル名は、店舗名、機種名、`台データ比較` をつなげた名前にします
- 台データ比較のCSVには `曜日` 列と `特定日` 列を出し、画面で選んだ末尾、毎月の日付、ゾロ目、曜日に該当する日は `はい`、それ以外の日は `いいえ` として確認できます
- 日付は保存済みの `YYYY-MM-DD` を基準に扱い、環境による時差で前日にずれないようにしています
- 各ページには前の一覧へ戻るための導線を置いています

## 軽量化について

- 通常のページ表示で `Supabase` の読み出しは行いません
- GUIアプリの取得後にR2上の表示用JSONを更新し、WebアプリはR2の公開URLだけを読む形に寄せています
- 表示用JSONが無い環境では、Supabaseやgit上のJSONへ戻らず、データなしとして扱います
- 取得結果を短時間だけ使い回したい場合は、必要に応じて `HALLDATA_FETCH_CACHE_TTL_MS` でミリ秒単位に変更できます
- 外部書体の読み込みをやめ、端末に入っている日本語書体を使います
- 重いぼかし背景と初期表示時の動きを外し、表の描画を優先しています
