- `店舗横断バックテスト` の結果表、店舗ページ、狙い度ランキング、バックテスト、台データの上部でも、店舗名の近くにある星から同じお気に入り登録・解除ができます
- `マイホール` に登録した店舗は、ドラッグで自由に並び替えできます
- `マイホール` は、保存順と近い順のラジオボタンで並びを切り替えられます。近い順では、選択中の登録住所を基準に、保存順と同じ細かさの店舗カードで並べ、地区名と距離は店舗名の下に小さく表示します。固定の登録住所として `住所1（太宰府市朱雀）` と `住所2（葛飾区青戸）` を初期表示します。距離は、CSV住所から作った店舗住所地点がある場合は選択住所の地点と店舗住所地点の直線距離で計算し、店舗住所地点がない場合だけ店舗地域代表地点を使います
- `マイホール` の保存先はブラウザー側の端末保存で、保存キーは `halldata-my-hall-store-ids` です
- Webアプリは、表示用のマイホールとしてクラウド側を読みません。従来どおりブラウザー側の端末保存だけを読みます
- Webアプリを開いた時と、星の追加・解除や並び替えを行った時に、ブラウザー側のマイホールをR2上の `my-hall/index.json` へ控えとして書きます。この控えはGUIアプリが読むためのもので、Web側の表示には混ぜません
- 差枚の表示基準で `みんレポ基準` を選んでいる場合でも、みんレポ由来またはSセブン由来の差枚がない行は、その行だけ `設定1基準` の差枚を表示します。保存済みの設定1基準差枚がない場合は、G数・BB・RBから表示時に計算します
- `狙い度ランキング` の期待値列は、期待RBは `1/310` 以下、期待割は `102%` 以上の場合だけ表示・強調します。期待RBは `RB1/297.6` や `RB270` のような分母目安だけを使い、`RB2,397` のようなRB回数は候補に含めません。見送り条件は期待値候補から外し、条件列は一致数の数字だけを表示します
- `狙い度ランキング` と `店舗横断狙い度ランキング` の結果表では、各行をクリックまたはタップすると、ホバーで表示していた採用目安、条件、期待割、期待RB、補足情報を行の下に展開表示します
- `店舗横断狙い度ランキング` では、マイホール登録済み店舗をチェック形式で選び、選択店舗にあるジャグラー系機種のうち期待RBが表示できる候補だけを機種ごとのランキング表に表示します。対象店舗チェック欄は `福岡の店舗`、`東京の店舗`、`その他の店舗` に分けて表示します。結果表には `店舗名` 列を追加し、選択機種内ランキングの全体表は出しません。共通狙い度ロジック、機種別ロジック、採用条件は画面内で選ばず、各店舗に保存されている設定を店舗ごとに使います。翌営業日実績は候補行に残し、後から打つ価値があったかを確認できます。対象店舗のチェック状態はブラウザー側の端末保存で復元し、保存キーは `cross-store-hunt-ranking-selected-store-ids` です。全店舗は上部ボタン、福岡の店舗と東京の店舗は各グループ内のボタンでまとめてON/OFFできます。選択した狙い度の日に保存データがない店舗でも、指定日以前の直近保存日がある場合はその日を基準に表示し、該当する店舗名列だけを茶色背景にします。基準日は行のホバー表示で確認できます。指定日以前の保存データがない店舗や読み込めない店舗は、その店舗だけを横断結果から除外し、他の店舗の表示を続けます
- `店舗一覧` では、保存済み店舗を都道府県ごと、さらに地域ごとに分けて表示します
- `店舗一覧` では、都道府県内の地域を広い画面で4列、画面幅に応じて3列、2列、1列へ切り替えて表示します
- `店舗一覧` では、住所を複数登録し、その中から選択した住所を基準に、地域の並びを `通常の地域順` と `自宅地域から近い順` で切り替えられます。福岡県太宰府市は店舗が未登録でも住所候補として選べます。登録住所はブラウザー側の端末保存にだけ入れ、Cloudflare側には保存しません。距離はアプリ内に持たせた住所地点同士の直線距離で計算し、店舗住所地点がない場合だけ地域の代表地点を使います
- `店舗一覧` の地域ごとの一覧は折りたたみ式で、初期表示では閉じています
- `店舗一覧` の地域ごとの一覧は、展開しても地域ブロックの並び順と位置が入れ替わらないように表示します
- 店舗名で検索した時は、該当店舗が見えるように地域ごとの一覧を開いた状態で表示します
- 登録済みでも台データが未取得の店舗は一覧に表示し、店舗ページでは未取得案内を出します
- みんレポ上の都道府県単位の店舗一覧を元に、店舗追加や登録情報補完を先に行い、台データ未取得の店舗ページだけ先に公開する運用もできます
- 店舗の追加や編集はGUIアプリで行い、Web側では登録操作を行いません
- `機種一覧` の上部には店舗名、元ページへのリンク、`狙い度ランキング` と `バックテスト` へのリンク、狙い度ロジックの切替を表示します
- 狙い度対象機種がある店舗の `機種一覧` では、各機種行に `検証` 列を表示し、検証ボタンから機種別ロジック検証ページを開けます
- `機種一覧` では、表の上に追加の見出しを置かず、すぐ機種表を表示します
- `機種一覧` では、各機種ごとの最新記録日を基準に、保存済みの機種をリンク付きの表で見られます
- `台データ` の上部には機種名、店舗名、機種一覧へ戻るリンク、店舗ページを開くリンク、狙い度ロジックの切替を表示します
- `狙い度ランキング` の上部には店舗切り替えの選択欄を表示します。選択肢は `マイホール` と `その他の店舗` に分け、別店舗を選ぶとその店舗の狙い度ランキングへ移動します
- `ロジック検証` ページでは、機種別ページと同じ表示列、差枚列の表示基準、狙い度計算の差枚基準、設定推定基準、期間、特定日条件、紫強調条件を使い、紫強調に該当した台だけを判定履歴と翌日実績のまとまりで表示します。設定上位モードでは、翌日実績の設定列の数値が高い台を順位範囲と最低G数で抽出できます。判定履歴の日数は適用中の狙い度ロジックが参照する日数に合わせ、カード内は翌日実績、判定日、過去履歴の順に表示します。同じ日に複数カードがある場合は、その日ごとに横並びで表示します
- 機種別ページとロジック検証ページの表示期間、表示列、設定推定基準、紫強調条件、検証の抽出方法は、ブラウザー側に保存し、リロード後も復元します。表示期間は全店舗、全機種、通常ページ、検証ページで共通保存し、未保存時の初期値は直近14日です。表示期間を反映すると共通の保存値が更新され、次に別店舗や別機種のページを開いた時も同じ表示期間を最初の表示から使います。保存済み表示期間の確認前に既定の直近14日表を一瞬表示しないため、古い保存値だけが残っている環境では保存確認中の表示を挟んでから表を出します。ロジック検証ページでは設定推測の入力値も保存します。差枚列の表示基準と狙い度計算の差枚基準は、古い保存値があっても通常表示では復元せず、みんレポ基準を初期値として使います
- `台データ` では、同じ台番のデータを日付ごとに比較できます
- `台データ` の設定推測用スペック表は、初期状態では閉じた折りたたみ表示にしています
- トップページ、店舗ページ、狙い度ランキングページ、バックテストページ、機種ページの上部見出しは、トップページの `保存済み店舗` と同程度の文字サイズで表示します
- 各ページの上部では、表示元の表記を出さず、画面の目的と操作導線を優先します

## データの読み出し

- Web表示では、Cloudflare R2 の公開URLにある表示用JSONだけを読みます
- Web表示用JSONの店舗索引には、GUIアプリの登録店舗で保存した都道府県と地域も含めます
- Web表示用JSONの店舗索引と店舗概要には、GUIアプリがみんレポの `旧イベント日` から取得した特定日条件も含めます。条件は日付末尾、毎月の日付、ゾロ目、曜日に分けて保存します
- 店舗概要JSONの都道府県や地域が古い場合でも、店舗索引にある登録済みの都道府県と地域を優先して表示に使います
- 店舗一覧、機種一覧、台データ、狙い度ランキング、バックテストはR2上の表示用JSONだけを読んで表示します
- 表示用JSONは店舗概要と機種別データに分けて保存し、機種ページでは必要な機種のJSONだけを読みます
- 狙い度ランキング、店舗横断狙い度ランキング、バックテストは、初回表示では店舗概要JSONだけを読み、結果表示時にチェックした対象機種のJSONを同時に読み込みます
- 狙い度ランキングの保存済み計算は、使用ロジック、差枚基準、設定推定基準、日付範囲、対象機種に加えて、機種別評価用に広げた履歴日数も分けて扱います。機種別評価が必要な画面では、通常の狙い度だけの保存済み計算を流用せず、評価に必要な履歴を含む計算結果を使います
- 表示用JSONが無い環境では、WebアプリはSupabaseやgit上のJSONへ戻らず、データなしとして扱います
- R2の公開URLは `CLOUDFLARE_R2_PUBLIC_BASE_URL` に設定します。`r2.dev` の公開URLか、R2に割り当てた独自ドメインを入れます
- ローカル確認時は、ルートの `.env.local` も読めるようにしています
- 本番の `Vercel` では、同じ環境変数を `Vercel` 側に設定する想定です
- 既存のCSV退避データは、`stores_rows.csv` と `machine_daily_results_rows.csv` から `python apps/gui/web_data_export.py --source csv` でR2へ移行できます
- 既存の `apps/web/public/halldata-static` は `python apps/gui/migrate_static_web_data_to_r2.py` でR2へ移行できます

## 表示について

- 画面全体は白と薄い灰色を基調にし、装飾を抑えた表示にしています

- 店舗一覧は表示用JSONの索引だけを読み、台データ行は読みません
- 機種一覧は、表示用JSONにある機種要約を優先して表示します

## 軽量化について

- 通常のページ表示で `Supabase` の読み出しは行いません
- GUIアプリの取得後にR2上の表示用JSONを更新し、WebアプリはR2の公開URLだけを読む形に寄せています
- 表示用JSONが無い環境では、Supabaseやgit上のJSONへ戻らず、データなしとして扱います
- 取得結果を短時間だけ使い回したい場合は、必要に応じて `HALLDATA_FETCH_CACHE_TTL_MS` でミリ秒単位に変更できます
- 外部書体の読み込みをやめ、端末に入っている日本語書体を使います
- 重いぼかし背景と初期表示時の動きを外し、表の描画を優先しています
