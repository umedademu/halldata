# Webサイトの現状

## 画面構成

- `apps/web` に `Vercel` 向けのサイトを用意しています
- ページの流れは `店舗一覧 → 機種一覧 → 台データ` です
- 狙い度対象店舗の店舗ページ上部には、`狙い度ランキング` と `バックテスト` への導線があります
- ブラウザーのタブ名は固定ではなく、`店舗一覧`、各店舗の `機種一覧`、`狙い度ランキング`、`バックテスト`、各機種の `台データ` に応じて切り替わります
- `店舗一覧` では、保存済みの店舗名を検索して絞り込めます
- `店舗一覧` では、保存済みの店舗名をシンプルな文字リンクとして見られます
- 店舗の追加や編集はGUIアプリで行い、Web側では登録操作を行いません
- `機種一覧` の上部には店舗名と元ページへのリンクだけを表示します。ただし狙い度対象店舗では `狙い度ランキング` と `バックテスト` へのリンクも表示します
- `機種一覧` では、表の上に追加の見出しを置かず、すぐ機種表を表示します
- `機種一覧` では、各機種ごとの最新記録日を基準に、保存済みの機種をリンク付きの表で見られます
- `台データ` の上部には機種名、店舗名、機種一覧へ戻るリンク、店舗ページを開くリンクだけを表示します
- `台データ` では、同じ台番のデータを日付ごとに比較できます
- `台データ` の設定推測用スペック表は、初期状態では閉じた折りたたみ表示にしています
- トップページ、店舗ページ、狙い度ランキングページ、バックテストページ、機種ページの上部見出しは、トップページの `保存済み店舗` と同程度の文字サイズで表示します
- 各ページの上部には、小さく `表示元: JSON` を表示します

## データの読み出し

- Web表示では、Cloudflare R2 の公開URLにある表示用JSONだけを読みます
- 店舗一覧、機種一覧、台データ、狙い度ランキング、バックテストはR2上の表示用JSONだけを読んで表示します
- 表示用JSONは店舗概要と機種別データに分けて保存し、機種ページでは必要な機種のJSONだけを読みます
- 狙い度ランキングとバックテストは、初回表示では店舗概要JSONだけを読み、結果表示時に対象機種のJSONを同時に読み込みます
- 表示用JSONが無い環境では、WebアプリはSupabaseやgit上のJSONへ戻らず、データなしとして扱います
- R2の公開URLは `CLOUDFLARE_R2_PUBLIC_BASE_URL` に設定します。`r2.dev` の公開URLか、R2に割り当てた独自ドメインを入れます
- ローカル確認時は、ルートの `.env.local` も読めるようにしています
- 本番の `Vercel` では、同じ環境変数を `Vercel` 側に設定する想定です
- 既存のCSV退避データは、`stores_rows.csv` と `machine_daily_results_rows.csv` から `python apps/gui/web_data_export.py --source csv` でR2へ移行できます
- 既存の `apps/web/public/halldata-static` は `python apps/gui/migrate_static_web_data_to_r2.py` でR2へ移行できます

## 表示について

- 画面全体は白と薄い灰色を基調にし、装飾を抑えた表示にしています
- `PC` と `スマホ` の両方で、左端の日付列を固定した横長の比較表で見られます
- `スマホ` では店舗一覧、機種一覧、台データ比較の表を横に動かしながら確認します
- 店舗一覧は表示用JSONの索引だけを読み、台データ行は読みません
- 機種一覧は、表示用JSONにある機種要約を優先して表示します
- 表示用JSONが使えない環境では、機種一覧や台データは表示できません
- 機種一覧の台数、平均差枚、平均G数、平均出率は、それぞれの機種にとって最新の日一日分をもとに表示します
- 機種一覧は、まず機種ごとの最新日が新しい順、その次に台数の多い順で表示します
- `ゴーゴージャグラー3` と `ゴーゴージャグラー３` のような機種名の表記ゆれは、設定ファイルをもとに同じ機種としてまとめて表示します
- `ネオアイムジャグラーEX` と `SアイムジャグラーＥＸ` が両方ある店舗では、機種一覧に統合ページの `アイムジャグラーEX` を出し、その下に個別ページの2機種をインデントして表示します
- `新ハナビ` と `スマスロ ハナビ` が両方ある店舗では、機種一覧に統合ページの `ハナビ` を出し、その下に個別ページの2機種をインデントして表示します
- 差枚計算条件がある機種では `G数`、`BB`、`RB` から `ボーナス数基準差枚` を作り、保存済みの差枚とは別に表示用JSONへ持たせます
- 差枚の計算条件と機種名の表記寄せはルートの `config/machine_difference_rules.json` にまとめてあり、今は `ネオアイムジャグラーEX`、`SアイムジャグラーＥＸ`、`マイジャグラー`、`ゴーゴージャグラー`、`ファンキージャグラー`、`ミスタージャグラー`、`ジャグラーガールズ`、`ウルトラミラクルジャグラー`、`ハッピージャグラー`、`ニューキングハナハナ`、`キングハナハナ`、`ハナハナホウオウ`、`スマスロ ハナビ`、`新ハナビ`、`スターハナハナ`、`ドラゴンハナハナ～閃光～` を登録済みです
- この条件ファイルは、Web側では主に機種名の表記寄せに使うため、`apps/web/config/machine_difference_rules.json` にも同梱しています
- Webサイトでは `ボーナス数基準差枚` を表示用JSONから読むだけにし、表示時の差枚逆算は行いません
- 台データ比較では、横幅を抑えるために表内の日付を `YY/MM/DD` 形式で表示し、日付の隣に曜日を表示し、数値の桁区切りを省いています
- 台データ比較は、表示用JSON内の機種別データを読みます
- `アイムジャグラーEX` や `ハナビ` の統合ページでは、列見出しに `ネオアイム 101番台`、`Sアイム 201番台` のように元機種が分かる名前を付けます
- 台データ比較では、チェックボックスで表示する列を選べます
- 台データ比較の `出率`、`BB率`、`RB率` は初期状態では非表示です
- アイムジャグラーEX系、スマスロ ハナビ、新ハナビ、スマスロ サンダーV、バーサスリヴァイズ、ハナハナホウオウ、ニューキングハナハナ、キングハナハナ、スターハナハナ、ドラゴンハナハナ～閃光～、ファンキージャグラー2、マイジャグラーV、ハッピージャグラーV、ゴーゴージャグラー、ジャグラーガールズ、ウルトラミラクルジャグラー、ミスタージャグラーの台データ比較では、`G数`、`BB`、`RB` から別アプリと同じ計算方法で設定を推測し、`設定` 列に加重平均値を表示します
- 対応機種の台データ比較では、`データ推測`、`G数による推測`、`特定日6あり` の比重を入力できます
- `狙い度` 列がある対応機種では、`データ推測` の入力欄の下で、順位範囲、狙い度下限、偏差値下限、順位の見方、偏差値の比較対象、順位・狙い度・偏差値の判定方法、順位と偏差値に使う機種を指定できます。初期値は順位 `1` から `3`、狙い度 `70` 以上、偏差値 `60` 以上、チェック機種内順位、チェック機種内偏差値、どれか一致、ジャグラー系機種のみチェック済みです
- 機種別ページの表示期間、日付強調条件、差枚の基準、表示列、設定推測の比重、狙い度強調条件、表示条件、設定推測、狙い度の開閉状態はブラウザー側に店舗単位で保存し、次回同じ店舗の機種別ページを開いた時に復元します
- 機種別ページでは、条件に合う `狙い度` と `偏差値` のセルを薄紫の背景と太字で強調します
- `G数による推測` は標準で `6000G` から `9000G` までを指数 `1.5` で評価し、指数を大きくすると後半ほど評価が伸びやすくなります
- `特定日6あり` は、店舗ごとに保存している特定日行だけ、その機種の中で最も良い台を高く見る相対評価として使います
- `特定日6あり` の比較に使う元の評価は、`G数による推測` がオフならデータ推測だけ、オンならデータ推測とG数推測を合わせた値です

- バックテストでは、翌営業日実績の日付末尾 `0` から `9` と曜日を複数選び、特定日別の結果を確認できます
- `Aパーク春日店` と `A-PARK屋形原` のバックテストは、初回表示では日付末尾 `0`、土曜、日曜を選択済みにします
- バックテストで選んだ日付末尾と曜日はブラウザー側へ保存し、次回以降も前回使った値を復元します
- 機種別の台データ表、狙い度ランキング、バックテストの `差枚` は、`ボーナス数基準` と `みんレポ基準` の2択で切り替えられ、初期値は `ボーナス数基準` です
- バックテスト条件の送信はブラウザー標準の `GET` で行い、選んだ条件はURLにも反映します
- `ボーナス数基準` では、GUIアプリの保存時または既存データ更新処理で作った `ボーナス数基準差枚` を使います
- バックテストの `機械割` は、選択中の差枚を使い、どちらの基準でも `1Gあたり3枚投入` で計算します
- `みんレポ基準` では、保存済みの翌営業日差枚をそのまま使います
- 狙い度ランキングの `差枚` 列も、選択中の差枚基準に合わせて表示します
- バックテストの順位条件は開始順位と終了順位で指定でき、例えば `1位から3位` のように日ごとの順位範囲で翌営業日の実績を集計します
- 順位条件は `全機種順位`、`チェック機種内順位`、`機種内順位` を切り替えられます
- `チェック機種内順位` を選んだ場合は、その日にチェックを入れた機種全体の中で順位を付けます
- `機種内順位` を選んだ場合は、その日に選択中の各機種それぞれの中で上位を拾うため、例えば3機種を選んで `1位から3位` にすると、各日で最大9台分が条件一致になります
- 偏差値条件は順位条件とは別に、`全機種内`、`チェック機種内`、`機種内` のどれを比較対象にするかを選べます
- バックテストの狙い度条件と偏差値条件は下限値で指定でき、例えば `90以上` や `60以上` のように日ごとの下限で翌営業日の実績を集計します。偏差値下限の初期値は `60` です
- 順位条件、狙い度条件、偏差値条件は1つだけでも複数でも使え、複数入れた時は `すべて一致` と `どれか一致` を選べます
- バックテストでは `グラフ表示` のオンとオフを選べ、初期状態はオンです
- グラフ表示をオンにすると、`翌営業日の日付` を横軸、`その時点までの累積差枚` を縦軸にした折れ線グラフを表示します
- バックテストの結果は `全合算`、`翌営業日が末尾の日`、`翌営業日が指定曜日`、`通常日` に分けて表示します
- それぞれのバックテスト結果は `機種別` と `総計` で分けて表示し、`条件一致台数` `狙い度` `偏差値` `実績集計台数` `合計差枚` `合計G数` `BB` `RB` `BB率` `RB率` `合成` `機械割` `平均設定` を確認できます
- バックテスト結果の `狙い度` と `偏差値` は、条件一致した台の平均値です
- バックテスト結果の `BB` と `RB` は、それぞれ翌営業日実績の `BIG` 合計回数と `REG` 合計回数です
- バックテスト結果の `BB率` と `RB率` は、各行の `合計G数` を `BB` または `RB` の合計で割った値を `1/○○` 形式で表示します
- バックテスト結果の `合成` は、各行の `合計G数` を `BB+RB` の合計で割った値を `1/○○` 形式で表示します
- バックテスト結果には `この条件を目印にする` ボタンを追加し、保存した目印条件を同じ店舗の `狙い度上位` 一覧へ反映できます
- 目印条件の強調判定には、機種選択、順位条件、順位の見方、狙い度条件、偏差値条件、偏差値の比較対象、複数条件を併用した時の一致方法を使います
- バックテストの期間は目印の保存情報として別表示できますが、`狙い度上位` 一覧で強調するかどうかの条件文や判定には含めません
- `狙い度上位` 一覧では、一番左に `条件` 列を出し、目印条件に一致する行だけ `★` を表示します
- 翌営業日の実績がまだ無い台は `条件一致台数` には含めますが、`実績集計台数` と差枚合計などの実績集計からは外します
- `狙い度ランキング` では `条件`、`順位`、`4/29狙い度`、`偏差値`、`機種名`、`台番`、`4/30差枚`、`4/30G数`、`4/30BB`、`4/30RB`、`4/30合成`、`4/30設定` のように、狙い度の日と実績の日を列名に入れて表示します。`4/30出率`、`4/30BB率`、`4/30RB率` はチェックボックスで追加表示できます
- `狙い度ランキング` の `機種名` を押すと、その店舗の該当機種の `台データ` ページへ移動できます
- `狙い度ランキング` の一覧は、`翌営業日設定` が `3.50` 以上の行全体を、機種ごとページの `設定` 列と同じ色で塗り分けます
- 対応機種の台データページでは、設定別の `BIG確率`、`REG確率`、`合成確率` を表示します
- 台データ比較は表示列を減らすと列幅と文字を大きくし、横幅は5台分の表示を上限にします
- 台データ比較の日付列は、列幅を広げても日付が見切れないよう固定幅を確保します
- 台データ比較では、台番と台番の境界が分かるように、各台番の右端の縦線を少し太く表示します
- 台データページでは、日付末尾の `0` から `9`、`ゾロ目`、曜日を複数選び、全日を表示したまま該当行だけを強調できます
- 日付末尾、ゾロ目、曜日は初期状態ではすべて未選択で、何も選んでいない時は日付条件による強調を行いません
- 選択済みの末尾、ゾロ目、曜日をもう一度押すと、その条件の強調を解除します
- 台データページで選んだ特定日の末尾、ゾロ目、曜日は画面上の一時的な切り替えとして使います
- 台データページの比較表は、表示期間を `直近◯日` と `開始日〜終了日` のカレンダー指定で切り替えられます
- 台データページの比較表の初期表示は `直近14日` で、直近指定は保存済み最新日を基準に数えます
- 台データページの日付条件は絞り込みには使わず、ページ全体を読み込み直さずに画面内の強調だけを切り替えます
- 台データ比較の表は、「CSV出力」ボタンで表示中の列をCSVファイルとしてダウンロードできます
- 台データ比較のCSVには `曜日` 列と `特定日` 列を出し、画面で選んだ末尾、ゾロ目、曜日に該当する日は `はい`、それ以外の日は `いいえ` として確認できます
- 日付は保存済みの `YYYY-MM-DD` を基準に扱い、環境による時差で前日にずれないようにしています
- 各ページには前の一覧へ戻るための導線を置いています

## 軽量化について

- 通常のページ表示で `Supabase` の読み出しは行いません
- GUIアプリの取得後にR2上の表示用JSONを更新し、WebアプリはR2の公開URLだけを読む形に寄せています
- 表示用JSONが無い環境では、Supabaseやgit上のJSONへ戻らず、データなしとして扱います
- 取得結果を短時間だけ使い回したい場合は、必要に応じて `HALLDATA_FETCH_CACHE_TTL_MS` でミリ秒単位に変更できます
- 外部書体の読み込みをやめ、端末に入っている日本語書体を使います
- 重いぼかし背景と初期表示時の動きを外し、表の描画を優先しています
