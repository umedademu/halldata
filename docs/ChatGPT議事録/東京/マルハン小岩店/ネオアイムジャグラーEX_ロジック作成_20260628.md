## 2. 高内容日の定義

ネオアイムジャグラーEXなので、単純な差枚や機械割ではなく、設定5・6級に座れた可能性を最重要指標にしました。プロンプト指定どおり、BIG/RBの設定別確率から各台の設定1〜6推定率を対数尤度で計算し、設定5・6推定率を「56級ヒット率」の代理指標にしました。

評価ラベルは以下です。

| 指標        | 扱い                              |
| --------- | ------------------------------- |
| 設定5・6推定率  | 最重要。平均・中央値・50%以上割合・70%以上割合を見る   |
| RB確率      | ネオアイムの段階条件名の主軸                  |
| 合算確率      | RBの裏付けとして確認                     |
| 差枚/機械割    | 最後に確認。RBや56推定率を犠牲にして高機械割だけを追わない |
| CSV内の設定列  | 最終ロジックの説明変数には不使用                |
| 狙度/次差/ブドウ | 最終ロジックの説明変数には不使用                |

成功寄りの評価は「設定5・6推定率50%以上」、強ヒットは「設定5・6推定率70%以上」としました。設定4以下は今回の目的では失敗寄りとして扱います。

## 12. 実戦での使い方

毎日の順位付けには100点ロジックを使います。まず70点未満、危険条件2個以上、履歴7日未満は見送り寄りです。

Webアプリの条件列では、RB310級、RB300級、RB290級、RB280級、RB270級参考の順に表示します。最本命参考は件数10のため、表示はしても過信しない注意書きを付けるべきです。

## 13. 最終結論

この機種では、**100点満点ロジックは毎日の候補順位付けに使う**のが最も現実的です。ただし、実戦で座るかどうかの主軸は、点数そのものより **自由度MAX条件の深沈み＋低G** を優先した方が良いです。

最終優先順位は以下です。

| 優先 | 使うもの     | 判断                         |
| -: | -------- | -------------------------- |
|  1 | 見送り条件    | 危険2個以上、履歴不足、前日大幅プラスなどを先に除外 |
|  2 | 自由度MAX条件 | 深沈み＋低Gを最優先                 |
|  3 | 段階的採用条件  | RB290級、RB280級は強いが件数注意      |
|  4 | 100点ロジック | 毎日の順位付け、70点/80点の足切り        |
|  5 | 次点差      | 3点以上だけ補助。8点以上の過信は禁止        |

結論として、実装は **全日共通ロジックのみ** でよいです。通常日・特定日専用ロジックは、今回は作らない方が安全です。

## 13. 最終結論

この機種では、**100点満点ロジックを主軸にしすぎない方がよい**です。100点ロジックは毎日の候補順位付けには有効ですが、56推定率を本当に上げるには、点数よりも **深沈み＋RB未処遇＋前日凹み＋適度な56間隔** の複合条件を優先すべきです。

最も現実的な運用は以下です。

1. Webアプリの `機種別` 列で100点ロジックを見る。
2. `条件` 列で `弱本命300` 以上が出ている台を優先。
3. `最本命270` が出たら、点数ロジックより優先してよい。
4. ただし、処遇完了・56直後・長期放置・低稼働が重なれば見送り。
5. `1位＋次点差10以上` は、段階条件がない日の補助候補に留める。

通常日専用・特定日専用ロジックは作らず、**全日共通ロジックのみ実装**でよいです。
