以下、CSVから作成した **メッセ扇店・ネオアイムジャグラーEX用の狙い台ロジック正本** です。
この回答は、分析レポートではなく、あとでCodexがWebアプリへ実装できる「実装用の正本」を最後に固定する前提で作っています。
最新日の行は未完成データの可能性があるため除外し、狙い度計算には当日前に分からない未来情報を使っていません。
また、`特定日` はCSVの `はい/いいえ` だけを正とし、日付や曜日そのものの加点には使っていません。
ネオアイムは設定5・6推定率を最重要指標、設定4以下を失敗寄りとして扱う特例に従い、設定推定率はBIG/REGの設定別確率から算出しています。

# 結論

**最優先で実装すべき本命条件は、自由度MAX条件の `自由本命RB1/297_REG返済未完` です。**

この条件は、64台選択で **RB 1/297.0、合算 1/140.7、平均差枚 +238.3枚、機械割 101.86%、平均設定5・6推定率 37.1%、設定5・6推定率50%以上割合 29.7%** でした。
ネオアイムとしては、平均機械割よりも **RBの軽さ、合算、設定5・6推定率の分布** を優先するため、この条件を点数ロジックより上位の実戦本命ルールとして扱います。

100点満点ロジックは、毎日の候補排序には使えますが、`score >= 80` 単体では広すぎてRB 1/328.8止まりです。したがって、Webアプリでは次の優先順にしてください。

1. **自由本命RB1/297_REG返済未完**：出た日は最優先
2. **弱め本命RB1/297_前日G保証**：本命補助
3. **広めRB1/305_連続高内容**：広めに候補を拾う入口
4. **見送り_高スコア処遇済み連敗**：スコアが高くても避ける

# 2. 高内容日の定義

ネオアイム特例として、設定5・6級に座れたかを成功の代理指標にしました。CSVの`設定`列は使わず、G数・BB・RBから各設定の尤度を計算し、以下を使いました。

| 指標            | 定義                         |
| ------------- | -------------------------- |
| `p56`         | 設定5推定率 + 設定6推定率            |
| `p4below`     | 設定1〜4推定率合計                 |
| `highContent` | `G >= 3000 && p56 >= 0.50` |
| `midHigh`     | `G >= 2500 && p56 >= 0.30` |
| `strongHigh`  | `G >= 4000 && p56 >= 0.70` |

評価優先順は **RB/REG確率 ＞ 合算確率 ＞ 機械割** です。
機械割が良くてもRBや設定5・6推定率が弱い条件は、上位採用にしていません。

# 13. 最終結論

この機種では、**100点満点ロジックを主軸に毎日の並びを作りつつ、実戦で座る条件は自由度MAX条件を最優先**にするのが最も現実的です。

通常日専用・イベント日専用ロジックは作りません。
Webアプリでは、全日共通100点ロジックを `機種別` 列に表示し、条件列に `自由本命RB1/297_REG返済未完`、`弱め本命RB1/297_前日G保証`、`広めRB1/305_連続高内容`、`見送り_高スコア処遇済み連敗` を表示してください。

# 検証方法
- Webアプリ上で実際にバックテストを回し、回答内に書いた採用条件ごとの選択台数、総G数、BB確率、RB/REG、合算、平均差枚、機械割と照合する
- Webアプリ側のバックテスト結果と回答内のバックテスト結果が、実用上許容できる範囲まで一致しない限り、実装完了扱いにしない
- ここでいう許容範囲は、選択台数、総G数、BB数、RB数などの母数がほぼ一致し、確率、機械割、平均差枚の差が丸め誤差や表示単位差で説明できる程度とする
- 回答内では整合しているのにWebアプリで一致しない場合は、条件式、最新日除外、未来情報除外、対象機種名、台番、履歴計算、通常日/イベント日の分岐、集計期間の違いを疑い、Webアプリ上で再検証しながら修正する
- ただし、同じ条件について主要なズレ原因を3つ確認しても一致しない場合、または30分以上かかる場合は、通常採用として有効化せず、未採用理由を照合ログに記録する
- 回答内の条件式、該当日付・台番一覧、集計表が最初から矛盾している条件は、Webアプリ側で無理に補正して合わせない
- 採用条件のラベル名や期待値表示だけを写して終わらせず、実際にWebアプリのバックテストで再現できる条件式に落とし込む
- 該当日付・台番一覧がある場合は、Webアプリの該当台と1件ずつ突き合わせる
- 順位、次点差、近隣、履歴不足の定義が曖昧な条件は、ラベルだけ実装せず参考条件として扱う
- Webアプリで回答値を再現できない条件は、通常採用条件として残さず、未採用理由を照合ログに記録する
- Webアプリ照合では、最初から全条件で設定分布を表示しない。原則OFFで主要成績を合わせ、設定推定率や設定分布が必要な条件だけ最終確認時にONにする
- Webアプリ実測ログと照合台帳を残すこと
