## 0. 前提

今回の目的は、分析レポートだけではなく、後でCodexがWebアプリへ迷わず実装できる「実装用の正本」を作ることとして扱いました。指示Markdownでも、最終成果物を分析レポートではなく実装用正本へ集約すること、途中仮説と最終採用条件を混ぜないことが指定されています。
また、条件式・該当日付台番一覧・バックテスト集計値がズレる条件は通常採用しない、という整合性ルールを最優先しました。

# 2. 高内容日の定義

ネオアイムジャグラーEXは、指示Markdownの特例どおり、設定5・6級に座れたかを成功の中心に置きました。設定4以下は、今回の狙い台ロジックでは失敗寄りとして扱います。

設定推定率は、G数・BB・RBを使って、設定1〜6のBIG確率とREG確率から尤度を出し、正規化して算出しました。最重要指標は `設定5・6推定率 = 設定5推定率 + 設定6推定率` です。

| 区分   | 定義                                                           |
| ---- | ------------------------------------------------------------ |
| 強高内容 | G >= 5000 && p56 >= 0.70 && rbRate <= 280 && combined <= 135 |
| 高内容  | G >= 3500 && p56 >= 0.50                                     |
| 準高内容 | G >= 3000 && p56 >= 0.30                                     |
| 弱内容  | G >= 2500 && p56 < 0.10 && combined >= 155 && rbRate > 400   |

`設定`列は最終ロジックの説明変数には使っていません。CSV実績のG数・BB・RBから再計算した設定5・6推定率だけを検証ラベルとして使いました。

# 3. 設定師のクセ仮説

一番強く見えたクセは、**直近で56っぽさが薄く、RBも枯れている台を、10〜28日程度の間隔で返す**動きです。特に `p56avg7 <= 0.10 && rbRate7 >= 460` は、実績RB 1/287.9、合算 1/135.7、平均p56 43.3%、中央値p56 54.2%で、今回の主軸です。

次に、**前日がほぼ低内容で、7日RBが極端に重い台**が強めでした。`rbRate7 >= 460 && prevP56 <= 0.05` はRB 1/295.1で、弱め本命として実戦投入できます。

一方で、**スコア1位が2位を大きく離す日**は逆に危険でした。`rank == 1 && topGap >= 8` はRB 1/441.8、平均p56 13.0%で、単独候補として目立ちすぎる台は放置台・極端な履歴枯れの可能性が高いです。

# 12. 実戦での使い方

毎日の順位付けには100点満点ロジックを使います。ただし、点数だけで座るのではなく、Webアプリの条件列で `本命RB290` または `強RB280` が付く台を優先してください。

実戦優先順位は次です。

1. `見送り単独暴走` に当たる台は、scoreが高くても避ける。
2. `強RB280` が出た台を最優先。
3. `本命RB290` が出た台を本命。
4. `弱め本命RB300` は候補が少ない日に打つ。
5. `広めRB310` は入口条件。単独では過信せず、score・危険条件・他条件重複を見る。
6. `最本命RB270参考` は表示してよいが、6件しかないため主軸にしない。

# 13. 最終結論

この機種では、**100点満点ロジック単体を主軸にするより、自由度MAXで見つかったRB枯れ・56空白条件を主軸にする方が実戦向き**です。

Webアプリ上では、100点満点ロジックを「機種別」列に表示し、条件列では `本命RB290` と `強RB280` を上位条件として出すのがよいです。通常日専用・イベント日専用ロジックは作らず、全日共通ロジックだけを実装してください。
