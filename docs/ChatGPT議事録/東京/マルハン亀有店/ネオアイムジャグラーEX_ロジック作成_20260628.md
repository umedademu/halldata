## 2. 高内容日の定義

ネオアイムジャグラーEXなので、単純な差枚や機械割ではなく、**設定5・6推定率**を主軸にしました。

各台日の `G数 / BB / RB` から、設定1〜6それぞれのBIG確率・REG確率で二項尤度を計算し、正規化して、

```text
設定5・6推定率 = 設定5推定率 + 設定6推定率
設定4以下推定率 = 設定1〜4推定率の合計
```

を出しました。ネオアイムでは、REG確率の設定差が大きい一方、BIGとREGを別々に見た設定推定率を使う指定があるため、この方式を採用しています。

## 13. 最終結論

この機種では、**100点満点ロジックを主軸に候補を作り、実戦投入は自由度MAX条件を最優先**にするのが最も現実的です。

| 判断          | 結論                                         |
| ----------- | ------------------------------------------ |
| 100点満点ロジック  | 毎日のランキング作成に使う                              |
| 段階的採用条件     | Webアプリ上で座る価値の強弱を表示する                       |
| 自由度MAX条件    | 実戦の最優先ルールにする                               |
| 通常日専用ロジック   | 作らない                                       |
| イベント日専用ロジック | 作らない                                       |
| 理由          | 特定日34日分では専用式が過剰最適化になりやすく、強いクセは全日共通で説明できるため |

実戦確認順は、

```text
1. 自由MAX主条件があるか
2. 75点以上 + 危険0 + 強化3以上か
3. 日別1位 + 70点以上 + 危険0か
4. 毎日1位の広め候補か
5. 危険条件・履歴不足がないか
```

です。

# 12. 実戦での使い方

## 毎日の順位付け

まずは100点満点ロジックで全台を並べます。
毎日1位はRB1/311.5、平均+385枚なので、順位付けとしては有効です。

## 条件が出た日だけ打つ本命ルール

優先順位は以下です。

1. **上位5＋21日RB1/310以下＋勢い＋危険0**
   最強。RB1/267.6、P56平均50.4%。ただし19件。
2. **60点以上＋危険0＋21日RB1/330以下＋勢い**
   実戦本命。RB1/283.7、P56>=50が46.3%。
3. **50点以上＋危険0＋強化2＋勢い**
   打てる日を増やす妥協。RB1/298.3。
4. **60点以上＋危険0＋強化3**
   広め候補。RB1/308.1。

## Webアプリ条件列で見る補助ルール

Webアプリでは、`機種別`列に100点ロジック、`条件`列に上記の段階条件を表示するのが良いです。
通常日専用・イベント日専用ロジックは今回は作らない方が良いです。理由は、通常日と特定日のベース差が小さく、強い条件も日付種別ではなく「長期RB・勢い・危険0」で説明できるためです。

# 13. 最終結論

| 判断                  | 結論                                        |
| ------------------- | ----------------------------------------- |
| 100点満点ロジックを主軸にするべきか | **順位付けの主軸にする**                            |
| 段階的採用条件を主軸にするべきか    | **Webアプリ表示の主軸にする**                        |
| 自由度MAX条件を主軸にするべきか   | **実際に座る最終判断では最優先**                        |
| 通常日/イベント日専用         | 作らない。全日共通のみ                               |
| 最も現実的な打ち方           | 100点で候補抽出 → 危険0確認 → 長期RBと勢い確認 → 段階条件で着席判断 |

この店舗のネオアイムは、**単純な高スコア順だけではなく、「長期RBの本物感」と「直近の勢い」が重なった台を優先する方が強い**です。

# 12. 実戦での使い方

毎日の順位付けには、100点満点ロジックを使います。ただし、点数1位を機械的に打つのは弱いです。

条件が出た日だけ打つ本命ルールは、以下の順番です。

1. **F5最本命**が出たら最優先
2. **F3本命**と**F4強条件**は積極的に候補
3. F1広めは、他に強条件がない日の補助候補
4. スコア上位でも、低G危険・長期放置・自由条件外なら見送り
5. 次点差15点以上は補助材料。単独では打たない

Webアプリの条件列では、F5、F3、F4、F1の順でラベル表示するのが良いです。

# 13. 最終結論

この機種では、**100点満点ロジックを主軸にして毎日1位を打つより、自由度MAX条件を主軸にする方が現実的**です。

| 判断         | 結論              |
| ---------- | --------------- |
| 100点満点ロジック | 毎日の順位付け・候補抽出用   |
| 段階的採用条件    | Webアプリ上の価値表示用   |
| 自由度MAX条件   | 実戦の主軸           |
| 最優先        | F5最本命           |
| 安定本命       | F3本命            |
| 強条件        | F4強条件           |
| 広め候補       | F1広め            |
| 見送り優先      | 低G危険、長期放置、深沈みだけ |

最終的な実戦順は、**自由度MAX条件 → 段階的採用条件 → 100点スコア順位 → 危険条件確認**です。

# 12. 実戦での使い方

毎日の順位付けには、100点満点ロジックを使います。ただし、点数1位を機械的に打つのは弱いです。

条件が出た日だけ打つ本命ルールは、以下の順番です。

1. **F5最本命**が出たら最優先
2. **F3本命**と**F4強条件**は積極的に候補
3. F1広めは、他に強条件がない日の補助候補
4. スコア上位でも、低G危険・長期放置・自由条件外なら見送り
5. 次点差15点以上は補助材料。単独では打たない

Webアプリの条件列では、F5、F3、F4、F1の順でラベル表示するのが良いです。

# 13. 最終結論

この機種では、**100点満点ロジックを主軸にして毎日1位を打つより、自由度MAX条件を主軸にする方が現実的**です。

| 判断         | 結論              |
| ---------- | --------------- |
| 100点満点ロジック | 毎日の順位付け・候補抽出用   |
| 段階的採用条件    | Webアプリ上の価値表示用   |
| 自由度MAX条件   | 実戦の主軸           |
| 最優先        | F5最本命           |
| 安定本命       | F3本命            |
| 強条件        | F4強条件           |
| 広め候補       | F1広め            |
| 見送り優先      | 低G危険、長期放置、深沈みだけ |

最終的な実戦順は、**自由度MAX条件 → 段階的採用条件 → 100点スコア順位 → 危険条件確認**です。

# 12. 実戦での使い方

## 毎日の順位付け

まずは100点満点ロジックで全台を並べます。
毎日1位はRB1/311.5、平均+385枚なので、順位付けとしては有効です。

## 条件が出た日だけ打つ本命ルール

優先順位は以下です。

1. **上位5＋21日RB1/310以下＋勢い＋危険0**
   最強。RB1/267.6、P56平均50.4%。ただし19件。
2. **60点以上＋危険0＋21日RB1/330以下＋勢い**
   実戦本命。RB1/283.7、P56>=50が46.3%。
3. **50点以上＋危険0＋強化2＋勢い**
   打てる日を増やす妥協。RB1/298.3。
4. **60点以上＋危険0＋強化3**
   広め候補。RB1/308.1。

## Webアプリ条件列で見る補助ルール

Webアプリでは、`機種別`列に100点ロジック、`条件`列に上記の段階条件を表示するのが良いです。
通常日専用・イベント日専用ロジックは今回は作らない方が良いです。理由は、通常日と特定日のベース差が小さく、強い条件も日付種別ではなく「長期RB・勢い・危険0」で説明できるためです。

# 13. 最終結論

| 判断                  | 結論                                        |
| ------------------- | ----------------------------------------- |
| 100点満点ロジックを主軸にするべきか | **順位付けの主軸にする**                            |
| 段階的採用条件を主軸にするべきか    | **Webアプリ表示の主軸にする**                        |
| 自由度MAX条件を主軸にするべきか   | **実際に座る最終判断では最優先**                        |
| 通常日/イベント日専用         | 作らない。全日共通のみ                               |
| 最も現実的な打ち方           | 100点で候補抽出 → 危険0確認 → 長期RBと勢い確認 → 段階条件で着席判断 |

この店舗のネオアイムは、**単純な高スコア順だけではなく、「長期RBの本物感」と「直近の勢い」が重なった台を優先する方が強い**です。

## 13. 最終結論

この機種では、**100点満点ロジックを主軸に候補を作り、実戦投入は自由度MAX条件を最優先**にするのが最も現実的です。

| 判断          | 結論                                         |
| ----------- | ------------------------------------------ |
| 100点満点ロジック  | 毎日のランキング作成に使う                              |
| 段階的採用条件     | Webアプリ上で座る価値の強弱を表示する                       |
| 自由度MAX条件    | 実戦の最優先ルールにする                               |
| 通常日専用ロジック   | 作らない                                       |
| イベント日専用ロジック | 作らない                                       |
| 理由          | 特定日34日分では専用式が過剰最適化になりやすく、強いクセは全日共通で説明できるため |

実戦確認順は、

```text
1. 自由MAX主条件があるか
2. 75点以上 + 危険0 + 強化3以上か
3. 日別1位 + 70点以上 + 危険0か
4. 毎日1位の広め候補か
5. 危険条件・履歴不足がないか
```

です。

```text

亀有ネオアイム_全日共通_返済未完×極端履歴スコア_v1

通常日専用ロジックとイベント日専用ロジック：
作らない。
CSVには「特定日」列があるが、通常日・特定日で主要なクセは共通しており、特定日側は34日分しかなく専用ロジック化すると過剰最適化リスクが高い。
Webアプリでは全日共通ロジックを「機種別」列に表示し、「通常日」「特定日」列にはこの店舗・機種専用の別スコアは表示しない、または「専用なし」とする。

Webアプリ上の表示方針：
- 機種別列：亀有ネオアイム_全日共通_返済未完×極端履歴スコア_v1 の100点スコアを表示
- 条件列：下記の段階的採用条件を表示
- 通常日列：専用ロジックなし
- 特定日列：専用ロジックなし
- 特定日そのものを点数加点に使わない
- 曜日そのものを点数加点に使わない
- 固定台番優遇をしない

ネオアイム用の設定推定率：
各台日の G数, BB数, RB数 から、設定1〜6のBIG確率・REG確率で二項尤度を計算する。
組み合わせ項は各設定で共通なので実装上は省略してよい。
設定確率：
設定1 BIG 1/273.1, REG 1/439.8
設定2 BIG 1/269.7, REG 1/399.6
設定3 BIG 1/269.7, REG 1/331.0
設定4 BIG 1/259.0, REG 1/315.1
設定5 BIG 1/259.0, REG 1/255.0
設定6 BIG 1/255.0, REG 1/255.0

対数尤度：
ll_s =
BB * log(pB_s) + (G - BB) * log(1 - pB_s)
+
RB * log(pR_s) + (G - RB) * log(1 - pR_s)

最大llを引いてexpし、合計1になるよう正規化する。
設定5・6推定率 = P(設定5) + P(設定6)
設定4以下推定率 = P(設定1) + P(設定2) + P(設定3) + P(設定4)

ネオアイムの成功判定：
設定5・6級だけを成功扱いにする。
設定4以下は失敗扱いにする。
設定5と設定6の区別はしない。
採用条件の評価では平均RBだけでなく、平均設定5・6推定率、中央値設定5・6推定率、設定5・6推定率50%以上割合、設定5・6推定率70%以上割合、設定5・6推定率30%未満割合、設定4以下推定率70%以上割合も表示・検証する。

点数計算に必要な履歴指標：
各台番単位で、当日より前の履歴だけを使う。
台番変更がある場合は履歴を接続せずリセットする。
必要な履歴：
- 直近3日,5日,7日,10日,14日,21日の合計差枚
- 直近3日,5日,7日,10日,14日,21日の合計G数
- 直近3日,5日,7日,10日,14日,21日のBB数, RB数
- 直近3日,5日,7日,10日,14日,21日のBB率, RB率, 合算
- 直近7日,10日,14日,21日の差枚角度 = 期間差枚 ÷ 期間G数 × 1000
- 直近7日,10日,14日,21日の高内容回数
- 高内容 = 設定5・6推定率50%以上
- 強高内容 = 設定5・6推定率70%以上
- 前回高内容からの営業日数
- 前回強高内容からの営業日数
- 現在連敗数
- 現在連勝数
- 前日G数, 前日差枚, 前日設定5・6推定率
- 日別スコア順位
- 日別1位と2位の点差
- 強化条件数
- 危険条件数

除外・禁止：

- 「狙度」「次差」「ブドウ」は最終ロジックの説明変数として使わない
