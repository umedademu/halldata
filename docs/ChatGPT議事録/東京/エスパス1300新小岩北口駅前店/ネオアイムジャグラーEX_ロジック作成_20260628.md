最新日の行は未完成データの可能性があるため除外し、狙度・次差など当日前に使えない加工列は説明変数から外しました。これはプロンプト指定どおりです。

### 台番変更・設置変更

CSV上では、全期間で同じ38台の台番列が維持されていました。
そのため、**台番変更による履歴リセットは不要**と判断しました。

ただし、履歴ロジックは最大21日を使うため、バックテストでは2026-02-05〜2026-02-25を履歴蓄積期間として除外しました。

### 特定日の扱い

`特定日`列は存在しましたが、最終スコアの点数項目には入れていません。日付・曜日・特定日そのものを直接加点しない指定に従い、特定日は比較検証だけに使いました。

結論として、**通常日専用ロジック・イベント日専用ロジックは作らず、全日共通ロジックのみ**でよいです。

理由は、特定日の全体成績は通常日より良いものの、強かった前兆パターンは通常日・特定日で大きく変わらず、イベント日は検証対象が30日しかないため、専用ロジック化すると過剰最適化になりやすいからです。

## 2. 高内容日の定義

ネオアイムジャグラーEXは特例として、**設定5・6級に座れたか**を最重要指標にしました。設定4以下は今回の目的では失敗扱いです。

各台日のG数・BB・RBから、ネオアイムの設定1〜6のBIG確率・REG確率を使って設定推定率を計算しました。最重要指標は、設定5推定率＋設定6推定率です。

### 今回の検証ラベル

| ラベル      | 定義                                                          |
| -------- | ----------------------------------------------------------- |
| 設定5・6推定率 | 独自計算した設定5率＋設定6率                                             |
| 高内容      | G数4,000以上かつ設定5・6推定率50%以上、またはG数5,000以上かつRB1/300以下かつ合算1/140以下 |
| 高内容70    | G数4,000以上かつ設定5・6推定率70%以上                                    |
| 成功扱い     | 設定5・6推定率が高い台を多く拾えること                                        |
| 失敗扱い     | 設定4以下推定率が高い台、RB1/400超が多い台                                   |

CSV内の「設定」列は参考値として確認しましたが、最終ロジックには使っていません。最終ロジックは、実戦前に分かる過去履歴だけで計算します。

## 12. 実戦での使い方

### 毎日の順位付け

まず、全台に100点満点スコアを付けます。
基本は以下の順です。

1. 自由A〜Eが出ている台
2. 73点以上
3. 66点以上
4. 1位＋次点差10点以上
5. 64点以上
6. 61点以上は広め候補

### 条件が出た日だけ打つ本命ルール

最も優先すべきは、次の条件です。

**最本命継続型**
前日高内容70＋5日内高内容2回以上＋2日合算1/120以下＋7日合算1/140以下

この条件はRB1/265.6、平均56率49.7%、RB1/400超10.7%で、今回のデータでは最も実戦向きです。

## 13. 最終結論

この店舗のネオアイムは、**単純な凹み上げ店ではありません**。

一番強いのは、

**前日〜直近数日のボーナス内容が本物で、かつ継続・据え・返済未完の形になっている台**

### 主軸にすべきもの

| 用途           | 主軸                   |
| ------------ | -------------------- |

## 12. 実戦での使い方

### 毎日の順位付けに使うもの

まず100点ロジックで全台を並べ、**日別1位**を最初に確認します。日別1位の期待RBは1/303.8で、全体平均より明確に良いです。上位3台までは一応見てもよいですが、優先は1位です。

### 条件が出た日だけ打つ本命ルール

本命は以下の順で見ます。

1. **7日急沈み**：直近7日角度 <= -150枚/1000G
2. **7日上昇＋前日本物**：直近7日角度 >= +150 かつ 前日56推定50%以上
3. **前日70%＋7日内56級4回以上**：同一台を繰り返し使う癖
4. **前日70%＋前日+3000枚以上**：出た後も使うパターン

特に1と2は母数もあり、実戦向きです。

### Webアプリの条件列で確認する補助ルール

Webでは以下の優先順位で表示するのが良いです。

1. 最本命/RB270参考
2. 強/RB280参考
3. 本命/RB290
4. 弱本命/RB300
5. 広め/RB310
6. 自由A：7日急沈み
7. 自由C：7日上昇＋前日本物
8. 見送り警戒

同じ台が複数に重なる場合は、最上位の条件名を表示し、補助として自由条件ラベルも併記するのが実戦向きです。

## 13. 最終結論

この機種では、**100点満点ロジックだけを主軸にするより、100点ロジックで順位を作り、自由度MAX条件で最終判断する**のが最も現実的です。

| 判断            | 結論                    |
| ------------- | --------------------- |
| 100点満点ロジック    | 毎日の順位付けの主軸にする         |
| 段階的採用条件       | Webアプリの価値表示に使う        |
| 自由度MAX条件      | 実戦の最終判断では最優先          |
| 通常日/特定日専用ロジック | 作らない。全日共通のみ           |
| 最も実戦向き        | 7日急沈み、7日上昇＋前日本物       |
| 最も注意          | 前日大負け単独、長期沈みっぱなし、連敗単独 |

実戦での確認順は、**日別1位 → 7日急沈み → 7日上昇＋前日本物 → 前日70%以上の本物感 → 危険条件の有無**です。

## 12. 実戦での使い方

毎日の順位付けは、まず `全日共通ロジック` を見ます。ただし、全日スコアだけで座るなら上位3または70点以上までが現実的で、75点以上だけにしてもRBは大きく改善しません。

本命ルールは、点数より `本物3点` を優先してください。全日なら「75点以上＋本物3点」、通常日なら「直近本物重なり」、特定日なら「特定強本命」が最も実戦向きです。

Webアプリの条件列では、以下の優先順がよいです。

1. 特定日：`特定強: RB270+14日プラス`
2. 通常日：`通常本命: 通常本物3点`
3. 全日：`弱め本命: 全日75+本物3点`
4. 代替：`広め: 全日70+急沈み`
5. 迷う台：危険条件2個以上なら見送り

## 13. 最終結論

この店舗のネオアイムは、**100点満点ロジックだけを主軸にするより、自由度MAX条件を主軸にするべき**です。

ただし、100点ロジックは不要ではありません。毎日の候補を広く並べる「地図」として使い、その上で本物3点・通常本物重なり・特定強本命を最終判断に使うのが最も現実的です。

結論は次です。

| 用途        | 主軸               |
| --------- | ---------------- |
| 毎日の順位付け   | 全日共通100点ロジック     |
| 通常日の本命判断  | 通常自由MAX: 直近本物重なり |
| 特定日の本命判断  | 特定自由MAX: 強本命     |
| Webアプリ条件列 | RB段階の採用条件        |
| 最終的に座るか   | 自由度MAX条件を最優先     |

実装すべき機種別ロジック名：
1. 新小岩北口_ネオアイム_全日共通_v1
2. 新小岩北口_ネオアイム_通常日_v1
3. 新小岩北口_ネオアイム_特定日_v1

通常日専用ロジックとイベント日専用ロジックを作るべきか：

理由：
通常日と特定日で成績差が明確にあり、特定日は専用条件でRB・合算・設定5・6推定率が大きく改善したため。

Webアプリ上の表示列：
- 全日共通ロジックは `機種別` 列に表示する。
- 狙い対象日が通常営業日なら `通常日` 列に通常日専用ロジックを表示する。
- 狙い対象日が特定日なら `特定日` 列にイベント日専用ロジックを表示する。
- 特定日はCSVまたはアプリ側データの `特定日=はい` のみを使う。日付末尾、曜日、外部イベント推測は使わない。

ネオアイムの評価方針：
- 設定5・6級だけを成功扱いにする。
- 設定4以下は失敗扱いにする。
- 設定5と設定6の区別は不要。
- 当日G数・当日BB・当日RB・当日差枚・当日設定表示・既存の狙度・次差は、当日の狙い度計算には使わない。
- 過去日のG数・BB・RBから、設定1〜6の推定率を再計算し、履歴指標として使う。
- 最重要表示指標は `設定5・6推定率 = 設定5推定率 + 設定6推定率`。
- 併記指標として、RB確率、合算確率、機械割、平均差枚、設定4以下推定率を表示する。

設定推定率の計算：
各履歴日の総G数を G、BIG回数を B、REG回数を R とする。
ネオアイムジャグラーEXの設定別確率は以下。
設定1: BIG 1/273.1, REG 1/439.8
設定2: BIG 1/269.7, REG 1/399.6
設定3: BIG 1/269.7, REG 1/331.0
設定4: BIG 1/259.0, REG 1/315.1
設定5: BIG 1/259.0, REG 1/255.0
設定6: BIG 1/255.0, REG 1/255.0

各設定 s の対数重み：
logC(G,B) + B*log(pB_s) + (G-B)*log(1-pB_s)
+
logC(G,R) + R*log(pR_s) + (G-R)*log(1-pR_s)

最大対数重みを引いてexpに戻し、合計1になるよう正規化する。
p56 = p5 + p6
p4down = p1 + p2 + p3 + p4

必要な履歴指標：
- history_days：同一台番で何日分の過去履歴があるか
- prev1_G数、prev1_差枚、prev1_BB、prev1_RB、prev1_p56
- prev3_G数_sum、prev3_BB_sum、prev3_RB_sum、prev3_差枚_sum
- prev5_G数_sum、prev5_BB_sum、prev5_RB_sum、prev5_差枚_sum
- prev7_G数_sum、prev7_BB_sum、prev7_RB_sum、prev7_差枚_sum
- prev14_G数_sum、prev14_差枚_sum
- prev3_rb_den = prev3_G数_sum / prev3_RB_sum
- prev5_rb_den = prev5_G数_sum / prev5_RB_sum
- prev7_rb_den = prev7_G数_sum / prev7_RB_sum
- prev7_gousei_den = prev7_G数_sum / (prev7_BB_sum + prev7_RB_sum)
- prev7_diff_per_1000g = prev7_差枚_sum / prev7_G数_sum * 1000
- loss_streak：直近の差枚マイナス連続日数
