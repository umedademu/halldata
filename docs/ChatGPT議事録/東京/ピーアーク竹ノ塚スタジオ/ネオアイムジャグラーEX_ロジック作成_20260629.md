添付プロンプトが「分析レポートではなく、CodexがWebアプリへ実装できる正本」を最終目的にしているため、最後に **実装用正本** と **Codex貼り付け用 実装依頼** へ集約しました。
CSVの最新日除外・未来情報禁止のルールに従い、2026-06-17は除外し、各実績日は前日までの履歴だけで判定しています。
ネオアイムジャグラーEXは、設定5・6推定率を最重要の成功代理指標として扱い、設定別BIG/REG確率と対数尤度で各台のp56を計算しました。
機械割は `100 + 総差枚 ÷ 総G数 ÷ 3 × 100` で計算しています。

## 結論

ピーアーク竹ノ塚スタジオのネオアイムは、単純な「凹み上げ」よりも、**前日までに高内容を見せた台を、高稼働が付いている間だけ続けて使うクセ**が一番強く出ました。

最も実戦向きなのは次の順です。

1. **自由MAX_前日高内容×高稼働**
   `prevHighContent && g3 >= 16000 && g14 >= 60000`
   RB 1/282.7、平均p56 42.6%。点数が75未満でも優先する条件です。

2. **Neo本命_SCORE83**
   `score >= 83`
   RB 1/278.3、平均p56 41.9%。件数18なので強いが、5月寄りのため過信は禁物です。

3. **Neo広め_SCORE75 / Neo弱め本命_SCORE80**
   広めに拾う入口。RBは1/302〜1/299で、ネオアイムの段階条件として実装可です。

4. **見送り_RB7過熱非据え**
   `rbRate7 <= 280 && !prevHighContent`
   直近7日のRBだけ軽いが前日高内容ではない台は、実績RB 1/437.3、p56>=50%が0%。見送り条件として採用します。

# 3. ネオアイム設定推定率

ネオアイムジャグラーEXは設定5・6級だけを成功扱いにする。
設定4以下は今回の狙い台ロジックでは失敗寄りとして扱う。

設定別ボーナス確率：
| 設定 | BIG確率 | REG確率 | 合成確率 |
|---|---:|---:|---:|
| 1 | 1/273.1 | 1/439.8 | 1/168.48 |
| 2 | 1/269.7 | 1/399.6 | 1/161.02 |
| 3 | 1/269.7 | 1/331.0 | 1/148.61 |
| 4 | 1/259.0 | 1/315.1 | 1/142.15 |
| 5 | 1/259.0 | 1/255.0 | 1/128.49 |
| 6 | 1/255.0 | 1/255.0 | 1/127.50 |

p56計算：
G=総G数、B=BB、R=RB。
各設定sのBIG確率pB、REG確率pRを使い、
logWeight_s =
B * log(pB) + (G - B) * log(1 - pB)
+
R * log(pR) + (G - R) * log(1 - pR)

最大logWeightを引いてexpで戻し、設定1〜6で正規化する。
p56 = p5 + p6
p4lower = p1 + p2 + p3 + p4

組み合わせ項は設定間比較ではG/B/R固定のため相対重みでは相殺される。ただし既存実装が組み合わせ項込みでも、正規化後の設定比率は実用上同じになる想定。

# 16. 実装後の検証方法

必須完了条件：
- Webアプリ上で実際にバックテストを回し、回答内に書いた採用条件ごとの選択台数、総G数、BB確率、RB/REG、合算、平均差枚、機械割と照合する
- Webアプリ側のバックテスト結果と回答内のバックテスト結果が、実用上許容できる範囲まで一致しない限り、実装完了扱いにしない
- ここでいう許容範囲は、選択台数、総G数、BB数、RB数などの母数がほぼ一致し、確率、機械割、平均差枚の差が丸め誤差や表示単位差で説明できる程度とする
- 回答内では整合しているのにWebアプリで一致しない場合は、条件式、最新日除外、未来情報除外、対象機種名、台番、履歴計算、通常日/イベント日の分岐、集計期間の違いを疑い、Webアプリ上で再検証しながら修正する
- ただし、同じ条件について主要なズレ原因を3つ確認しても一致しない場合、または30分以上かかる場合は、通常採用として有効化せず、未採用理由を照合ログに記録する
- 回答内の条件式、該当日付・台番一覧、集計表が最初から矛盾している条件は、Webアプリ側で無理に補正して合わせない
- 採用条件のラベル名や期待値表示だけを写して終わらせず、実際にWebアプリのバックテストで再現できる条件式に落とし込む
- 該当日付・台番一覧がある場合は、Webアプリの該当台と1件ずつ突き合わせる
- 順位、次点差、近隣、履歴不足の定義が曖昧な条件は、ラベルだけ実装せず参考条件として扱う
- Webアプリで回答値を再現できない条件は、通常採用条件として残さず、未採用理由を照合ログに記録する
- Webアプリ照合では、最初から全条件で設定分布を表示しない。原則OFFで主要成績を合わせ、設定推定率や設定分布が必要な条件だけ最終確認時にONにする
