CSVを読み込み、添付プロンプトの「分析レポートではなくCodexが実装できる正本を作る」という前提でまとめました。
対象がネオアイムジャグラーEXなので、平均差枚や機械割よりも「設定5・6推定率」とRB/REGを主軸にしています。 設定5・6推定率は、G数・BB・RBから設定1〜6の尤度を出し、設定5＋6の確率として計算しました。

## 結論

この店のネオアイムは、**28日累計差枚で深く沈んでいる台を返すクセ**が最も強いです。逆に、**28日累計で大きくプラス、かつ前日56級でしっかり出た台**はRBが重く、56推定率も落ちるため危険です。

最終的な実戦優先順位は次です。

1. **自由MAX 連続高内容×未返済**
   `historyDays >= 28 && highCount3 >= 2 && diff28 <= 0`
   RB 1/267.8、合算 1/130.9、機械割104.43%。点数条件より優先してよい本命条件です。

2. **80点以上（最本命）**
   `historyDays >= 28 && score >= 80`
   RB 1/270.1、合算 1/134.6。件数は85台で少なめですが、最上位条件として通常採用可です。

3. **70点以上 / 75点以上**
   70点以上はRB 1/281.4、75点以上はRB 1/279.3。Webアプリの段階表示ではここから通常採用にします。

通常日専用・イベント日専用ロジックは作らず、**全日共通ロジックのみ**にします。特定日全体と通常日の差は小さく、特定日だけに加点するよりも、28日沈み・未返済・処遇完了を見た方が再現性が高いためです。

logWeight_s =
logC(G, B) + B * log(pB_s) + (G - B) * log(1 - pB_s)
+
logC(G, R) + R * log(pR_s) + (G - R) * log(1 - pR_s)

正規化：
maxLog = max(logWeight_1..logWeight_6)
weight_s = exp(logWeight_s - maxLog)
prob_s = weight_s / sum(weight_1..weight_6)

設定5・6推定率：
p56 = prob_5 + prob_6

p4lower = prob_1 + prob_2 + prob_3 + prob_4
