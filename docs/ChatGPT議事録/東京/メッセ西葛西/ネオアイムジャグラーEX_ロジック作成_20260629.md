# 3. 高内容・設定推定率の定義

設定推定率：
- 各台のG数、BB、RBから設定1〜6の対数尤度を計算する。
- 組み合わせ項は設定間で共通なので省略してよい。
- 最大対数尤度を引いてexpし、合計1に正規化する。
- p56 = 設定5推定率 + 設定6推定率
- p4low = 1 - p56

高内容定義：
highContent =
(
  G >= 3000 && p56 >= 0.50
)
||
(
  G >= 5000 && RB >= 18 && combinedRate <= 140
)

strongHighContent =
G >= 4000 && p56 >= 0.70

semiHighContent =
G >= 3000 && p56 >= 0.30

ネオアイムの成功判定：
設定5・6級だけを成功。
設定4以下は失敗扱い。
Webアプリ用の段階条件は期待RB基準で表示するが、採用判断は平均56率、中央値56率、56率50%以上、56率30%未満、RB、合算、平均差枚を併記して判断する。

# 16. 検証方法・実装完了条件

必ずWebアプリ上で実際にバックテストを回し、回答内に書いた採用条件ごとの選択台数、総G数、BB確率、RB/REG、合算、平均差枚、機械割と照合する。

許容範囲：
- 選択台数、総G数、BB数、RB数などの母数がほぼ一致すること
- 確率、機械割、平均差枚の差が丸め誤差や表示単位差で説明できること

一致しない場合に確認すること：
1. 最新日2026-06-19を除外しているか
2. Webアプリ入力期間が予測日基準で2026-02-21〜2026-06-17になっているか
3. 実績日基準では2026-02-22〜2026-06-18になっているか
4. 2026-03-30で全台履歴リセットしているか
5. historyDays >= 14 を適用しているか
6. 設定列やブドウ列を特徴量に使っていないか
7. score、boostCount、dangerCountの定義が本依頼と一致しているか
8. rank/topGapの母集団と同点処理が一致しているか
9. 通常日/特定日で勝手に分岐していないか
10. 条件式と該当一覧を1件ずつ照合しているか

設定分布表示：
最初からONにしない。
主要成績は原則OFFで照合する。
設定推定率や設定分布を確認する最終段階だけONにする。
ON/OFFで選択台数、総G数、BB、RB、差枚、機械割が変わる場合は、表示切替ではなく条件式・期間・履歴計算の問題を疑う。

照合ログ：

同じ条件について主要なズレ原因を3つ確認しても一致しない場合、または30分以上かかる場合は、通常採用として有効化せず、未採用理由を照合ログに記録する。
