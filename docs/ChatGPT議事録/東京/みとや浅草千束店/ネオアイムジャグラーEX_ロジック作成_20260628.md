## 2. 高内容日の定義

ネオアイムは、**設定5・6級に座れたかだけを成功寄りに評価**しました。設定4以下は今回の目的では成功扱いにしていません。

設定推定は、CSV内の`設定`列を使わず、指定されたBIG/REG確率から、各台日ごとに設定1〜6の重みを対数尤度で計算し、正規化して算出しました。

使った評価指標は次の通りです。

| p56    | 設定5推定率 + 設定6推定率                |

## 12. 実戦での使い方

毎日の順位付けは、**100点満点ロジックの1位**をまず見ます。ただし、1位でも危険条件があるなら評価を下げます。

条件が出た日だけ打つ本命ルールは、次の順です。

1. **自由A：1位＋次点差15以上＋危険0**
2. **最本命270：1位＋80点以上＋次点差12以上＋危険0**
3. **自由B：80点以上＋強化4個以上＋危険0**
4. **強280：1位＋80点以上＋次点差5以上＋危険0**
5. **本命290：80点以上＋危険0**
6. **弱本命300：1位＋70点以上＋次点差5以上＋危険0**
7. **広め310：1位＋危険0**

Webアプリの条件列では、上の段階条件を表示し、危険条件が1個以上ある場合は**本命表示より見送り警告を優先**するのが良いです。

## 13. 最終結論

この機種では、**100点満点ロジックは順位付けの土台として使い、実戦では自由B・次点差・危険0を主軸にする**のが最も現実的です。

| 判断                | 結論                                |
| ----------------- | --------------------------------- |
| 100点満点ロジックを主軸にするか | 単独主軸ではなく、毎日の順位付け用                 |
| 段階的採用条件を主軸にするか    | Web表示・座る価値の強弱判断に使う                |
| 自由度MAX条件を主軸にするか   | **実戦主軸。特に自由Bは優先度高**               |
| 通常日/特定日専用ロジック     | 作らない。件数不足で過剰最適化リスク                |
| 実戦確認順             | 危険0 → 自由A/B → 次点差 → 段階条件 → 100点順位 |

## 13. 最終結論

この店舗のネオアイムは、**単純な前日凹み・長期空き狙いではなく、直近5日〜14日の高稼働沈みと、処遇未完了感を重視するべき**です。

実戦優先順位は以下です。

1. **自由度MAX条件**
   `5日高稼働沈み＋直近14日高内容1回以下`
2. **75点以上＋危険0**
3. **72点以上＋危険0**
4. **次点差6点以上の1位**
5. **55〜60点台は、危険0かつ強化条件が複数ある時だけ**

結論としては、**100点満点ロジックを順位付けの土台にしつつ、実戦の主軸は自由度MAX条件にする**のが最も現実的です。
