## 2. マイジャグラーV 設定推定率

設定推定率は、CSVの設定列を使わず、各台日の G数、BB、RB から計算する。

設定別確率:
設定1 BIG 1/273.1, REG 1/409.6, 合成 1/163.8
設定2 BIG 1/270.8, REG 1/385.5, 合成 1/159.1
設定3 BIG 1/266.4, REG 1/336.1, 合成 1/148.6
設定4 BIG 1/254.0, REG 1/290.0, 合成 1/135.4
設定5 BIG 1/240.1, REG 1/268.6, 合成 1/126.8
設定6 BIG 1/229.1, REG 1/229.1, 合成 1/114.6

計算:
G = G数
B = BB
R = RB
pB = 設定別BIG確率
pR = 設定別REG確率

logWeight(setting) =
B * log(pB) + (G - B) * log(1 - pB)
+
R * log(pR) + (G - R) * log(1 - pR)

最大logWeightを引いてexpし、設定1〜6の合計が1になるよう正規化する。

p4plus = p4 + p5 + p6
p5plus = p5 + p6
p3minus = p1 + p2 + p3

マイジャグラーVの成功指標:
設定4以上推定率 = p4plus
設定5以上推定率 = p5plus
設定3以下推定率 = p3minus
設定6単独は成功目標にしない。

- 回答内では整合しているのにWebアプリで一致しない場合は、条件式、最新日除外、未来情報除外、対象機種名、台番、履歴計算、通常日/イベント日の分岐、集計期間の違いを疑う
- 同じ条件について主要なズレ原因を3つ確認しても一致しない場合、または30分以上かかる場合は、通常採用として有効化せず、未採用理由を照合ログに記録する
- 回答内の条件式、該当日付・台番一覧、集計表が最初から矛盾している条件は、Webアプリ側で無理に補正して合わせない
- 採用条件のラベル名や期待値表示だけを写して終わらせず、実際にWebアプリのバックテストで再現できる条件式に落とし込む
- 該当日付・台番一覧がある場合は、Webアプリの該当台と1件ずつ突き合わせる
- 順位、次点差、近隣、履歴不足の定義が曖昧な条件は、ラベルだけ実装せず参考条件として扱う
- Webアプリで回答値を再現できない条件は、通常採用条件として残さず、未採用理由を照合ログに記録する
- Webアプリ照合では、最初から全条件で設定分布を表示しない。原則OFFで主要成績を合わせ、設定推定率や設定分布が必要な条件だけ最終確認時にONにする
