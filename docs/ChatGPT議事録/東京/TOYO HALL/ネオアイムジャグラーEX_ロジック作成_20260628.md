以下は、添付CSVを読み込んで作成した **TOYO HALL／ネオアイムジャグラーEX 実装用ロジック正本** です。
今回の成果物は、単なる分析レポートではなく、後でCodexがWebアプリへ迷わず実装できる正本として固定します。これは添付プロンプトの「最終目的」に沿ったものです。

ネオアイムジャグラーEXは、設定5・6級だけを成功、設定4以下を失敗寄りとして扱う特例機種です。
そのため、平均差枚や機械割だけでなく、BIG/REGから推定した **設定5・6推定率** を最重要指標にしました。推定率は、指定された設定別BIG/REG確率と二項尤度の正規化で算出しています。
Webアプリ用の段階条件は、ネオアイム指定どおり期待RB 1/310、1/300、1/290、1/280、1/270の段階を意識しています。

## 3. 見えたクセ

一番強かったのは、**直近で稼働が付いていて、同台または近隣に内容の痕跡があり、かつ周辺がまだ返済されていない台** でした。単純な「凹み台」ではなく、`prevP56`、`semiHighCount7`、`rbRate5/7`、`neighborDiff7` が絡むとRBが軽くなりました。

弱かったのは、**直近3日無敗、直近弱内容の連続、近隣がすでに出ている台、RBが直近5日で重い台** です。特に `lossCount3 == 0` はRB 1/394.15、機械割97.32%まで落ちるため、強い見送り条件にしました。

## 9. 実戦での使い方

最優先は **見送り_直近3日無敗** の除外です。これに当たる台は、点数が高くても評価を落としてください。次に、`本命_本物感周辺沈み` が出ている台を本命視し、なければ `弱め本命_周辺沈み安全`、さらに広く拾うなら `広め_安全ブースト` を見ます。

100点満点ロジックは毎日の順位付け用です。
実戦の主軸は、点数単体ではなく **通常採用3条件＋見送り条件** です。

toyoHallNeoAimCommonScoreV1

通常日専用ロジックとイベント日専用ロジック：
作らない。
理由：CSVには特定日列があるが、履歴21日以上のバックテスト対象ではイベント日が13日しかなく、専用式は過剰最適化になりやすい。特定日だから加点、曜日だから加点という直接加点は禁止。全日共通ロジックだけを実装し、Webアプリでは「機種別」列に表示する。

対象期間：
- CSV読み込み期間：2026-02-06〜2026-06-06
- 除外した最新日：2026-06-06
- 履歴計算開始日：2026-02-06
- 回答内バックテストの実績日範囲：2026-02-27〜2026-06-05
- Webアプリで入力すべき予測日基準期間：2026-02-26〜2026-06-04
- 理由：Webアプリが「予測日を入力し、翌営業日実績を集計」する前提の場合、回答内の実績日より1日早い予測日を入力する必要がある。
- 履歴不足：historyDays < 21 は採用条件対象外。scoreは最大40にキャップする。

台番：
300, 301, 302, 303, 304, 305, 306

台番変更・増減台・島変更：
なし。履歴リセット日は設定しない。

除外する説明変数：
- 設定
- ブドウ
- 狙い度、狙度、次差などの当日前に分からない列
ただし、設定5・6推定率は、設定列ではなく、過去または実績日のG数・BB・RBから二項尤度で算出する評価指標として使う。

ネオアイム評価方針：
- 設定5・6級だけを成功扱いにする。
- 設定4以下は失敗寄りとして扱う。
- Webアプリ用の段階的採用条件は、期待機械割ではなく期待RBで並べる。
- 段階目安は、RB 1/310以下、1/300以下、1/290以下、1/280以下、1/270以下。
- ただし、RBだけで採用しない。設定5・6推定率、合算、平均差枚、件数を併記する。

G, B, R から各設定の対数尤度を計算し、最大対数尤度を引いてexpで戻し、合計1になるよう正規化する。
組み合わせ項は全設定で共通なので、実装上は省略しても正規化後の比率は同じ。ただし既存実装が指定式どおり組み合わせ項を含む場合はそのままでよい。

p56 = p5 + p6
p4minus = p1 + p2 + p3 + p4

高内容定義：
semiHigh:
(G >= 2000 && p56 >= 0.30) || (G >= 2500 && rbDen <= 330 && combinedDen <= 150)

highContent:
(G >= 2500 && p56 >= 0.50) || (G >= 3000 && rbDen <= 280 && combinedDen <= 140)

strongHigh:
(G >= 3000 && p56 >= 0.70) || (G >= 4500 && rbDen <= 240 && combinedDen <= 130)

lowContent:
G >= 1500 && p56 < 0.15

必要な履歴指標：
historyDays:
同一台番の過去営業日数。今回はリセットなし。

diffN:
同一台番の過去N日の差枚合計。

gN:
同一台番の過去N日のG数合計。

bbN:
同一台番の過去N日のBB合計。

rbN:
同一台番の過去N日のRB合計。

rbRateN:
gN / rbN。rbN == 0 の場合は Infinity。

combinedRateN:
gN / (bbN + rbN)。bbN + rbN == 0 の場合は Infinity。

angleN:
diffN / gN * 1000。gN == 0 の場合は nullまたは0扱いではなく低信頼扱い。

prevP56:
前日同一台番のG数・BB・RBから算出したp56。

prevDiff:
前日同一台番の差枚。

prevG:
前日同一台番のG数。

prevCombined:
前日同一台番の合算分母。

semiHighCountN:
同一台番の過去N日にsemiHighが成立した回数。

highContentCountN:
同一台番の過去N日にhighContentが成立した回数。

strongHighCountN:
同一台番の過去N日にstrongHighが成立した回数。

lowContentCountN:
同一台番の過去N日にlowContentが成立した回数。

lossCountN:
同一台番の過去N日のうち、G数 >= 500 && 差枚 < 0 の日数。

daysSinceSemiHigh:
直近のsemiHighから何営業日経過したか。前日semiHighなら1。過去にない場合はInfinity。

daysSinceHigh:
直近のhighContentから何営業日経過したか。前日highContentなら1。過去にない場合はInfinity。

daysSinceStrong:
直近のstrongHighから何営業日経過したか。前日strongHighなら1。過去にない場合はInfinity。

neighborDiff7:
同じ対象日の直前7営業日について、左右隣台の差枚合計。300番台は301のみ、306番台は305のみ。台番変更をまたいで接続しない。今回はリセットなし。

neighborSemiHigh7:
同じ対象日の直前7営業日について、左右隣台のsemiHigh回数。

boostCount:
以下6条件の成立数。
1. g5 >= 18000
2. semiHighCount7 >= 3
3. rbRate7 <= 330
4. diff10 <= -2000
5. prevP56 >= 0.30
6. neighborDiff7 <= -2000

dangerCount:
以下9条件の成立数。
1. lowContentCount3 >= 2
2. lossCount3 == 0
3. rbRate5 >= 400
4. combinedRate5 >= 166
5. neighborDiff7 >= 1000
6. diff10 >= 2500
7. semiHighCount7 == 0
8. daysSinceSemiHigh >= 7
9. g5 <= 7500

順位と次点差：
- 同一対象日、同一機種、historyDays >= 21 の台を母集団にする。
- score降順でdense rank。
- 同点は同順位。
- topGapは、その台のscoreから次に低い異なるscoreを引いた値。
- 次に低い異なるscoreがない場合は999。
- 見送り条件に当たる台も順位母集団には含める。ただし実戦表示では見送りラベルを優先する。
