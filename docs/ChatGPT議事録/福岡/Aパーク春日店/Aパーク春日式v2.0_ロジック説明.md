# Aパーク春日式v2.0 ロジック説明書

確認日: 2026-07-19

## この文書の目的

この文書は、このWebアプリを初めて見るChatGPTが、店舗内共通の狙い度ロジック「Aパーク春日式v2.0」の役割、入力値、計算式、画面上の扱い、注意点を、他の会話や資料がなくても理解できるようにするための説明書です。

結論から言うと、Aパーク春日式v2.0は、各台の基準日を含む直近7営業日の履歴から、次の営業日に狙う候補を探すための0〜100点の評価です。特に、負けが続き、差枚が沈み、途中で出た分も少なく、まだ十分に戻されていない台を高く評価します。

ただし、この点数は次の営業日の設定や勝利を保証する確率ではありません。過去の傾向に沿って候補の優先順位を付けるための評価値です。

## 最初に理解する全体像

Aパーク春日式v2.0の処理は、次の3段階です。

1. 直近7営業日の履歴から、旧「Aパーク春日式」の0〜100点を作る。
2. 「まだ戻されていない沈み台」を強め、「沈みが浅い台・連敗していない台・少台数機種」を弱める加減点を行う。
3. 補正後の点数を、理論範囲の-32〜138から画面用の0〜100点へ換算し、整数にする。

考え方を一言で表すと、次のとおりです。

> 直近7営業日で客側の負けが積み上がり、その間に大きな戻しがなく、直前まで沈みが続いている台を「返済未完了の候補」として上位にする。

## Webアプリ内での位置付け

このWebアプリには、大きく分けて次の2種類の評価があります。

| 種類 | 役割 | Aパーク春日式v2.0との関係 |
| --- | --- | --- |
| 店舗内共通の狙い度 | 対象機種へ同じ考え方を適用し、店舗内の候補を比較する | Aパーク春日式v2.0はこちら |
| 機種別評価 | ネオアイム、マイジャグラーなど、機種ごとに別の条件や点数を使う | Aパーク春日式v2.0とは別物 |

狙い度ランキング画面では、店舗内共通の点数は「共通」列、機種別評価は「機種別」列に表示されます。両方が高い台は有力候補として扱いやすくなりますが、両方の点数を作る計算は別々です。

Aパーク春日店の一部主要機種では、「Aパーク春日式v2.0が機種内1位」や「Aパーク春日式v2.0と機種別評価がともに機種内1位」だった過去実績が保存されています。画面の期待割、期待RB、補足表示、色分けにその実績が使われる場合がありますが、保存済み実績はAパーク春日式v2.0自体の点数計算には入りません。

## 日付の考え方

このロジックを理解するうえで、日付の区別が最重要です。

| 呼び方 | 意味 |
| --- | --- |
| 基準日 | 点数計算に使う最後の日。計算対象の7営業日に含まれる |
| 直近7営業日 | 基準日を含め、店舗に有効な実績がある営業日を新しい方から7日分たどった期間 |
| 狙い対象日 | 原則として基準日の次の営業日 |
| 実績日 | バックテストで答え合わせに使う狙い対象日 |

例えば、6月10日を基準日にした点数は、6月10日までに判明している履歴で作ります。バックテストでは、その次の営業日の実績と照合します。

コード内には「当日差枚」「当日推定設定」という名前がありますが、ここでいう当日は狙い対象日ではなく、点数計算の最後に含めた基準日です。将来日の実績を先に点数へ入れているわけではありません。

## 計算に使う主な元データ

1台・1営業日ごとの履歴から、主に次の値を使います。

- 店舗名
- 機種名
- 台番
- 営業日
- G数
- BB回数
- RB回数
- 差枚
- BB、RBなどから算出した推定設定

差枚は、画面で選ばれている差枚の扱いに従います。初期状態はみんレポ系の差枚です。サイトセブンのグラフ差枚がある行ではグラフ差枚が優先され、選択内容とデータの有無によってボーナスからの計算差枚などへ切り替わる場合があります。そのため、同じ日付・同じ台でも差枚の扱いを変えると点数が変わる可能性があります。

## 直近7営業日から作る8つの指標

### 1. 負け日数

直近7営業日のうち、差枚が0枚未満だった日数です。差枚0枚は負け日に数えません。

| 負け日数 | 加点 |
| ---: | ---: |
| 7日以上 | +25 |
| 6日 | +21 |
| 5日 | +16 |
| 4日 | +10 |
| 3日 | +5 |
| 2日以下 | 0 |

### 2. 現在連敗数

基準日から過去へ向かって、差枚が0枚未満の日が何日連続しているかを数えます。差枚が0枚以上の日に当たると連敗は止まります。

| 現在連敗数 | 加点 |
| ---: | ---: |
| 7連敗以上 | +18 |
| 6連敗 | +16 |
| 5連敗 | +14 |
| 4連敗 | +11 |
| 3連敗 | +8 |
| 2連敗 | +4 |
| 1連敗以下 | 0 |

### 3. 負け日の差枚絶対量合計

負けた日のマイナス差枚だけを正の数へ直して合計します。例えば、-1000枚と-500枚なら1500枚です。

| 負け差枚合計 | 加点 |
| ---: | ---: |
| 6000枚以上 | +18 |
| 5000枚以上 | +15 |
| 4000枚以上 | +12 |
| 3000枚以上 | +8 |
| 2000枚以上 | +4 |
| 2000枚未満 | 0 |

### 4. 7営業日の差枚合計

勝った日も負けた日も含めた直近7営業日の差枚合計です。より深く沈んでいるほど加点します。

| 差枚合計 | 加点 |
| ---: | ---: |
| -5000枚以下 | +14 |
| -4000枚以下 | +12 |
| -3000枚以下 | +9 |
| -2000枚以下 | +6 |
| -1000枚以下 | +3 |
| -1000枚より大きい | 0 |

### 5. 補填率

この文書ではコード上の名称に合わせて「補填率」と呼びます。既存の会話記録では「返済率」と表現される場合もあります。

計算式は次のとおりです。

```text
補填率 = プラスだった日の差枚合計 ÷ 負け日の差枚絶対量合計
```

例として、負け日の合計が4000枚、勝った日の合計が1000枚なら、補填率は0.25です。値が小さいほど、負けに対して戻した量が少ないとみなします。

| 補填率 | 加点 |
| ---: | ---: |
| 0.20以下 | +10 |
| 0.35以下 | +8 |
| 0.50以下 | +6 |
| 0.70以下 | +3 |
| 1.00以下 | +1 |
| 1.00より大きい | 0 |

負け日が1日もない場合は、0除算を避けるため内部的に999として扱い、この項目は0点になります。

### 6. 7営業日内の最大プラス差枚

直近7営業日のうち、最も大きく勝った日の差枚です。大きな見せ場がなかった台ほど加点します。

| 最大プラス差枚 | 加点 |
| ---: | ---: |
| 500枚以下 | +7 |
| 1000枚以下 | +5 |
| 1500枚以下 | +3 |
| 2000枚以下 | +1 |
| 2000枚より大きい | 0 |

プラスの日が1日もない場合は最大値が0枚となるため、+7点です。

### 7. 基準日の差枚

直近7営業日の最後の日、つまり基準日の差枚です。直前まで沈みが続いている台を少し強めます。

| 基準日の差枚 | 加点 |
| ---: | ---: |
| -2000枚以下 | +5 |
| -1000枚以下 | +4 |
| -500枚以下 | +3 |
| 0枚以下 | +2 |
| 1000枚以下 | +1 |
| 1000枚より大きい | 0 |

### 8. 基準日の推定設定

基準日のBB、RBなどからWebアプリが算出した推定設定の平均値です。弱い内容だった台を少し加点します。

| 推定設定 | 加点 |
| ---: | ---: |
| 2以下 | +3 |
| 3以下 | +2 |
| 4以下 | +1 |
| 4より大きい | 0 |

その機種に設定推測の定義がない場合や、推定できない場合は0点です。

## 第1段階: 旧Aパーク春日式の点数

前章の8項目を合計します。

```text
旧春日式点 =
  負け日数点
  + 現在連敗点
  + 負け日の差枚絶対量点
  + 7営業日差枚合計点
  + 補填率点
  + 最大プラス差枚点
  + 基準日差枚点
  + 基準日推定設定点
```

旧春日式点は0〜100の範囲です。この段階では、他の台の点数、店内順位、機種内順位、次点との差、イベント日、曜日、台番末尾などは使いません。

## 第2段階: v2.0の強弱補正

旧春日式点へ、次の条件をすべて個別に判定して加減点します。複数条件に当たれば、点数は重ねて加減されます。

### 加点

| 条件 | 補正 | 意味 |
| --- | ---: | --- |
| 負け日数が5〜6日、現在連敗が3以上、7営業日差枚合計が-3000枚以下のすべてを満たす | +18 | ほぼ負け続きで、直近も連敗し、全体でも深く沈んでいる |
| 現在連敗が4以上 | +8 | 直前まで強く負けが継続している |
| 7営業日差枚合計が-5000枚以下 | +8 | 期間全体の沈みが非常に深い |
| 補填率が0.35以下 | +4 | 負けに対して戻した量が少ない |

### 減点

| 条件 | 補正 | 意味 |
| --- | ---: | --- |
| 負け日数が4日以下 | -10 | 7営業日の大半を負けている形ではない |
| 現在連敗が1以下 | -6 | 直前まで負けが続いていない |
| 7営業日差枚合計が-2000枚より大きい | -6 | 沈みが浅い、またはプラスである |
| 基準日の同一機種の有効設置台数が1〜4台 | -10 | 少台数機種の偶然性や投入頻度を考慮して弱める |

最後の設置台数だけは、その台自身の履歴ではなく、基準日に同じ機種名で有効な実績を持つ台数を使う構造補正です。他の台の点数や成績順位を使う補正ではありません。

補正後の値を、この文書では「v2素点」と呼びます。

```text
v2素点 = 旧春日式点 + 加点の合計 - 減点の合計
```

## 第3段階: 0〜100点への換算

補正後の理論範囲を-32〜138として、次の式で0〜100へ換算します。

```text
換算前表示値 = (v2素点 + 32) ÷ 170 × 100
最終表示点 = 換算前表示値を0〜100に収め、四捨五入した整数
```

言い換えると、v2素点が-32なら0点、53なら50点、138なら100点です。

重要なのは、旧春日式点とv2.0の最終表示点は同じ尺度ではないことです。旧春日式点に補正を足したあと、もう一度0〜100へ換算するため、旧春日式点が70点でもv2.0の表示が70点になるとは限りません。

## 計算例

次のような台を例にします。

- 7営業日の差枚: -1000、-800、-600、-500、+200、-700、-400枚
- 負け日数: 6日
- 現在連敗: 2日
- 負け日の差枚絶対量合計: 4000枚
- 7営業日の差枚合計: -3800枚
- 補填率: 200 ÷ 4000 = 0.05
- 最大プラス差枚: 200枚
- 基準日の差枚: -400枚
- 基準日の推定設定: 2.5
- 同一機種の有効設置台数: 5台以上

旧春日式点は次のようになります。

```text
負け日数               21点
現在連敗                4点
負け日の差枚絶対量     12点
7営業日の差枚合計       9点
補填率                 10点
最大プラス差枚          7点
基準日の差枚            2点
基準日の推定設定        2点
----------------------------
旧春日式点             67点
```

v2.0の補正では、補填率0.35以下の+4点だけに当たり、他の加減点には当たりません。

```text
v2素点 = 67 + 4 = 71
最終表示点 = round((71 + 32) ÷ 170 × 100) = 61点
```

この例のように、旧春日式点よりv2.0表示点が小さくなる場合があります。これは減点されたからとは限らず、最後に-32〜138の範囲を0〜100へ換算しているためです。

## ランキングでの扱い

Aパーク春日式v2.0の計算そのものは、各台を固定条件で評価する絶対評価です。算出後に、Webアプリが表示点の高い順へ並べます。

- 最終表示点で並び替える。
- 同じ点数の場合は、機種名、台番の順で安定して並べる。
- 店舗全体の順位とは別に、画面側で機種内順位を判定する場面がある。
- 「機種内1位」は点数式の入力条件ではなく、点数を出した後の結果である。
- 機種別評価の点数や採用条件は、Aパーク春日式v2.0の点数へ足さない。
- 期待割や期待RBは保存済みバックテストの表示目安であり、Aパーク春日式v2.0の点数ではない。

したがって、「共通点が高い」「機種別点が高い」「採用条件に一致する」「期待割が高い」は、それぞれ別の情報として読む必要があります。

## 対象機種とロジックの選択

Aパーク春日店では、ジャグラー、ハナハナ、沖ドキ、スマスロなどを含む店舗共通の対象機種一覧がコードに定義されています。実際の画面では、その一覧と現在の店舗設置機種を照合し、該当する機種だけが計算対象になります。表記揺れとして登録された別名は、同じ機種名へ寄せて扱います。

実装上の識別名は次のとおりです。

| 画面上の名前 | 実装上の識別名 | 参照日数 |
| --- | --- | ---: |
| Aパーク春日式 | `apark` | 7営業日 |
| Aパーク春日式v2.0 | `apark-kai` | 7営業日 |
| Aパーク春日式v2.0 6日版 | `apark-kai-6` | 6営業日 |

注意点として、Aパーク春日店のコード上の初期値は現在も旧「Aパーク春日式」です。Aパーク春日式v2.0は選択可能な別ロジックとして実装されています。ブラウザーでは店舗ごとに最後に選んだロジックが保存されるため、検証時は画面の選択欄が「Aパーク春日式v2.0」になっていることを必ず確認してください。

6日版は似た名前ですが別の計算です。通常のv2.0を説明・検証する時に6日版の結果を混ぜてはいけません。

## データ不足時と境界値の注意

新しいChatGPTが計算を再現する時は、次の実装上の扱いに注意してください。

- 原則は基準日を含む7営業日だが、その台の行が一部欠けている場合、店舗の直近7営業日の範囲内に存在する行だけで計算を続ける場合がある。
- 差枚がちょうど0枚の日は負け日にも勝ち日にも数えず、現在連敗を止める。
- 「以下」「以上」は境界値を含む。例えば-3000枚は「-3000枚以下」に当たる。
- 「-2000枚より浅い」は、実装上は-2000枚より大きい場合であり、-2000枚ちょうどは減点しない。
- 推定設定が取れない機種は、基準日の推定設定点が0点になる。
- 負け日がない場合の補填率は内部的に999となり、補填率の加点はない。
- プラス日がない場合の最大プラス差枚は0枚となり、最大プラス差枚の項目は+7点になる。
- 同一機種の有効設置台数は、基準日に差枚、G数、BB、RBのいずれかに有効値がある台を数える。台数が0と判定された場合は少台数減点を行わない。
- 最終表示点は小数ではなく整数であり、0未満は0、100より大きい値は100へ収める。
- バックテストでは、基準日の点数と次の営業日の実績を照合する。基準日自身の実績を結果として集計しない。

## このロジックが見ていないもの

Aパーク春日式v2.0単体では、次の情報を点数に使いません。

- 次の営業日の実績
- 他台の狙い度点数や成績順位
- 機種別評価の点数
- 機種別採用条件への一致数
- 次点との差
- 保存済みの期待割、期待RB、勝率
- 曜日、日付末尾、イベント日
- 台番の末尾や角台かどうか
- 長期の投入間隔

画面にこれらの情報が同時表示されていても、Aパーク春日式v2.0の点数へ混ざっていると解釈してはいけません。

## 狙い度が高い時の正しい読み方

高得点は、主に次の状態を表します。

- 直近7営業日の負け日が多い。
- 直前まで連敗している。
- 負けた枚数の合計が大きい。
- 勝ち日を含めても7営業日合計が深くマイナスである。
- 負けた量に対して、勝ち日で戻した量が少ない。
- 7営業日内に大きなプラス日がない。
- 基準日も弱い結果で終わっている。
- 少台数機種ではない。

この状態を「次に必ず高設定が入る」と断定してはいけません。正しい説明は、「過去の検証で優先候補にしやすかった、未返済の沈み方に近い」です。

## ChatGPTがこの文書を使う時の確認手順

1. 店舗がAパーク春日店であることを確認する。
2. 選択中の共通狙い度が、旧式や6日版ではなく「Aパーク春日式v2.0」であることを確認する。
3. 基準日と、その次の狙い対象日を区別する。
4. 差枚の扱いが何に設定されているかを確認する。
5. 基準日を含む直近7営業日の各台データをそろえる。
6. 8項目から旧春日式点を計算する。
7. v2.0の加点・減点をすべて重ねる。
8. -32〜138の範囲を0〜100へ換算し、四捨五入する。
9. 共通点、機種別点、採用条件、期待値を別々の情報として比較する。
10. バックテストでは、点数を作った基準日の次の営業日実績と照合する。

## 最終要約

Aパーク春日式v2.0は、基準日を含む直近7営業日の負け日数、連敗、負け差枚、合計差枚、補填率、最大勝ち、基準日差枚、基準日推定設定から旧春日式点を作り、深い沈みと戻し不足を加点し、浅い沈み・連敗不足・少台数機種を減点して、次の営業日の候補を0〜100点で並べる店舗内共通ロジックです。
