## 2. 高内容日の定義

スマスロ東京喰種なので、ジャグラー系のRB最優先評価ではなく、**差枚・G数・機械割寄り**で高内容を定義しました。

```text
highContent =
  (G >= 3500 && (diff >= 1500 || payout >= 108))
  || (G >= 5000 && diff >= 500)

strongHigh =
  G >= 4500 && diff >= 3000
```

この高内容定義は、**過去履歴の評価にだけ使用**し、当日を判定する説明変数には使っていません。

# Webアプリ上のバックテスト照合方法
1. 最新日2026-06-28を除外する。
2. 履歴は台番ベースで計算し、2025-12-09と2026-04-21で必ずリセットする。
3. Webアプリ入力期間は予測日基準で、2025-07-12〜2025-12-06、2025-12-22〜2026-04-18、2026-05-04〜2026-06-26を使う。
4. 実績日は翌営業日として、回答内バックテスト実績日範囲と照合する。
5. 設定分布表示はOFFで確認する。
6. 各条件について、選択台数、総G数、BB、RB、差枚、平均差枚、機械割、勝率を照合する。
7. 該当日付・台番一覧とWebアプリ上の該当台を1件ずつ突き合わせる。

# 実装完了条件
- Webアプリ上で実際にバックテストを回し、回答内に書いた採用条件ごとの選択台数、総G数、BB確率、RB/REG、合算、平均差枚、機械割と照合する。
- Webアプリ側のバックテスト結果と回答内のバックテスト結果が、実用上許容できる範囲まで一致しない限り、実装完了扱いにしない。
- ここでいう許容範囲は、選択台数、総G数、BB数、RB数などの母数がほぼ一致し、確率、機械割、平均差枚の差が丸め誤差や表示単位差で説明できる程度とする。
- 回答内では整合しているのにWebアプリで一致しない場合は、条件式、最新日除外、未来情報除外、対象機種名、台番、履歴計算、通常日/イベント日の分岐、集計期間の違いを疑い、Webアプリ上で再検証しながら修正する。
