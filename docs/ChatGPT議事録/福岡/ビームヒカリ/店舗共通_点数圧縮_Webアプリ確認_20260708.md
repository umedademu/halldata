# ビームヒカリ 店舗共通点数圧縮 Webアプリ確認 2026-07-08

## 対象

- 店舗名: ビームヒカリ
- ロジック名: ビームヒカリ式1.0、ビームヒカリ1.0S
- 確認日: 2026-07-08
- 目的: 100点が多数並ぶ状態を抑え、上位候補同士の差を見やすくする

## 変更内容

- 元の加点合計は変更せず、元点全体を同じ倍率で表示点として圧縮する。
- 元120点を表示100点として扱う。
- 元の加点合計は `storeCommonRawScore` として保持する。
- 表示用の狙い度とランキング用の共通点数は、圧縮後の `storeCommonScore` を使う。
- 点数条件は圧縮前の `storeCommonRawScore` を見て判定し、既存バックテストの条件範囲を保つ。
- 古い保存済み狙い度計算を読まないよう、狙い度計算キャッシュを更新した。

## 条件表示の扱い

- ビームヒカリ式1.0の `SC_STAGE_REF_80_RISK0`、`SC_SKIP_SCORE75_RISK2`、`SC_SKIP_SCORE80_PREV_PROCESSED` は圧縮前の旧75点以上・旧80点以上の境界を使う。
- 表示点は一律圧縮するが、条件判定は圧縮前点数を使うため、従来の選択範囲を保つ。
- ビームヒカリ1.0Sの表示条件は、前2営業日のボーナス順位、前2営業日差枚、イベント判定が中心で、点数しきい値条件はない。
