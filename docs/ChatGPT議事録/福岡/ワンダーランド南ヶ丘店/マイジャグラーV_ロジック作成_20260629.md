## 2. 高内容日の定義

マイジャグラーVの設定推定は、BIG/REGを独立ベルヌーイ近似として設定1〜6の尤度を出し、正規化してp1〜p6を作りました。高内容は予測対象日自身ではなく、翌日以降の履歴ラベルとしてだけ使用します。

## 3. 設定師のクセ仮説

1. 最も強いのは「直近7〜21日で沈んでいるが、前日に高稼働またはRB良の痕跡がある台」。
2. 単なる長期放置より、前日G数6500以上や前日RB 1/300以下のように客に見える履歴が伴う台が強い。
3. 直近で合算が良すぎる、差枚が戻りすぎている台は処遇完了として弱い。危険_処遇完了型はRB 1/379.40、機械割99.04%まで悪化。
4. 通常日/特定日の専用式は作らない。日種別で出玉差はあるが、採用条件の核は同じで、日付種別そのものを加点する必要はない。

## 4. 検証したが弱かった仮説

- RB履歴だけが悪い台：過去RB率単独では未来成績に差が出にくかった。
- 出た台の据え置き狙い：直近7日差枚プラスかつ合算良好はRB/機械割が悪化。
- イベント日だけ狙い：サンプルが減る割に条件方向は共通で、日付種別加点は不要。
- 1/280級まで絞る条件：22台のみで過剰最適化。未採用。

## 6. サブ条件・信頼度ラベル

### 強化条件
boostCountは以下7条件の該当数。①diff7 <= -2000、②angle7 <= -65、③combinedRate7 >= 158、④daysSinceHighContent 8〜30または高内容未確認でhistoryDays>=28、⑤semiHighCount7 <= 1、⑥lossStreak >= 2、⑦prevRbRate <= 300 && prevCombinedRate <= 145 && prevGames >= 4500 && prevDiff <= 1500。

### 危険条件
dangerCountは以下9条件の該当数。①diff7 >= 2500、②diff14 >= 3500、③angle7 >= 80、④combinedRate7 <= 144、⑤highContentCount7 >= 3、⑥semiHighCount7 >= 4、⑦winStreak >= 2、⑧prevDiff >= 1800 && prevP4Plus >= 0.55、⑨games7 < 15000。

### 見送り条件
見送りは `dangerCount >= 3` または `diff7 >= 2500 && combinedRate7 <= 144` を警告ラベルにする。ただし、該当が広すぎるためWebアプリの通常採用条件にはしない。
