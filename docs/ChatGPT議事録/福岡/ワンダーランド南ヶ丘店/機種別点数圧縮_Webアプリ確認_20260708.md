## 目的

狙い度ランキングで機種別点数の100点が並び、台ごとの差が見えにくくなる状態を抑える。

## 反映内容

本質的な加点要素、危険判定、採用条件の考え方は変更せず、最終表示点だけを圧縮した。

80点以下は従来の点数を保つ。80点を超えた部分だけを緩やかに圧縮し、元点が高い台ほど表示点も高く残るようにする。

| 元点 | 表示点 |
| --- | --- |
| 75 | 75 |
| 80 | 80 |
| 90 | 85 |
| 100 | 89 |
| 106 | 90 |
| 110 | 92 |
| 120 | 94 |
| 130 | 95 |
| 140 | 96 |

## 採用条件の扱い

70点以上、75点以上、80点以上のような低中点の境界は、80点以下を変更しないため従来の意味をおおむね保つ。

今回の変更は「100点満点で上側が潰れていた表示」を直す目的であり、バックテスト条件そのものを作り直す変更ではない。

## 確認

- `node --check apps/web/lib/machine-evaluation.js` が成功
- `node --check apps/web/lib/data.js` が成功
- 圧縮表の確認で、75、80、90、100、106、110、120、130、140の表示点が想定どおりであることを確認
- `npm --prefix apps/web run build` が成功
- `http://localhost:3000/updates` が200で返り、今回の更新情報が含まれることを確認
- `http://localhost:3000/stores/store-065aa3087019/hunt-analysis` が200で返ることを確認
