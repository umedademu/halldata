## 2. 高内容日の定義

ファンキージャグラー特例に合わせ、評価優先度は **RB/REG確率 ＞ 合算確率 ＞ 設定推定率の分布 ＞ 機械割 ＞ 平均差枚** としました。ファンキージャグラーは設定5以上を成功目標とし、設定5・6推定率と設定4以下推定率を使う指定があるためです。

| 区分   | 定義                                                           |
| ---- | ------------------------------------------------------------ |
| 準高内容 | `G >= 2500 && rbDen <= 380 && combDen <= 155`                |
| 高内容  | `G >= 3000 && p56 >= 0.35 && rbDen <= 360 && combDen <= 150` |
| 強高内容 | `G >= 4000 && p56 >= 0.50 && rbDen <= 320 && combDen <= 140` |

`p56` は、プロンプト記載のファンキージャグラー設定別BIG/REG確率を使い、BIGとREGの二項尤度を正規化して算出しました。

# 16. Webアプリ照合方法

必ずWebアプリ上で実際にバックテストを回し、次を照合する。
- 選択台数
- 対象日数
- 総G数
- BB
- RB
- BB確率
- RB/REG確率
- 合算
- 合計差枚
- 平均差枚
- 機械割
- 勝率
- 該当日付・台番一覧

設定分布表示：
- 最初はOFFで主要集計を合わせる。
- 設定5・6推定率、設定4以下推定率の確認だけONにする。
- ON/OFFで選択台数、総G数、BB、RB、差枚、機械割が変わる場合は、設定分布表示ではなく条件式・期間・履歴計算のズレを疑う。

照合許容範囲：
- 選択台数、総G数、BB、RBはほぼ一致すること。
- BB確率、RB確率、合算、平均差枚、機械割は丸め誤差または表示単位差で説明できる範囲。
- Webアプリ側で一致しない場合は、最新日除外、予測日/実績日の1営業日ずれ、履歴リセット、対象機種名、台番、rank母集団、特定日分岐、G数0行の扱いを確認する。
- 同じ条件について主要なズレ原因を3つ確認しても一致しない場合、または30分以上かかる場合は通常採用として有効化せず、未採用理由を照合ログに記録する。
- 回答内の条件式、該当一覧、集計表が最初から矛盾している条件はWebアプリ側で無理に補正しない。ただし本依頼の通常採用・参考表示・見送り条件は回答内整合済み。

- ただし、同じ条件について主要なズレ原因を3つ確認しても一致しない場合、または30分以上かかる場合は、通常採用として有効化せず、未採用理由を照合ログに記録する。
- 回答内の条件式、該当日付・台番一覧、集計表が最初から矛盾している条件は、Webアプリ側で無理に補正して合わせない。
- 採用条件のラベル名や期待値表示だけを写して終わらせず、実際にWebアプリのバックテストで再現できる条件式に落とし込む。
- 該当日付・台番一覧がある場合は、Webアプリの該当台と1件ずつ突き合わせる。
- 順位、次点差、近隣、履歴不足の定義が曖昧な条件は、ラベルだけ実装せず参考条件として扱う。
- Webアプリで回答値を再現できない条件は、通常採用条件として残さず、未採用理由を照合ログに記録する。
- Webアプリ照合では、最初から全条件で設定分布を表示しない。原則OFFで主要成績を合わせ、設定推定率や設定分布が必要な条件だけ最終確認時にONにする。
