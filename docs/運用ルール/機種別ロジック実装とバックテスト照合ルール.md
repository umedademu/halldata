# 機種別ロジック実装とバックテスト照合ルール

この手順書は、店舗ごとの機種別ロジック、機種別採用条件、狙い度ロジック、ChatGPT回答ログ保存、Webアプリのバックテスト結果との照合、ChatGPT回答とWebアプリ実測値のすり合わせを行う時に必ず読む。

## 基本方針

機種別ロジックや採用条件は、コードへ実装しただけで完了にしない。

ChatGPT回答に含まれるバックテスト結果と、Webアプリ上で実際に出るバックテスト結果を照合し、許容できる水準まで一致してから完了扱いにする。

採用条件の名前だけを合わせて終わらせてはいけない。条件名、条件式、対象期間、集計件数、RB、合成、差枚、機械割まで確認する。

## ChatGPT回答ログの保存

ChatGPT回答原文は、店舗別フォルダへ保存する。

保存先の例:

- `docs/ChatGPT議事録/東京/店舗名/機種名_ロジック作成_YYYYMMDD.md`

原文が取得できない場合は、推測、要約、復元メモを作らない。原文が取れていないものを、取れたように見える形で残してはいけない。

原文未取得の場合は空ファイルにするか、管理上どうしても必要な場合だけ「原文未取得」と分かる最小限のメモにする。

## Webアプリ実測バックテストの保存

Webアプリ上で確認したバックテスト結果は、ChatGPT回答とは別に保存する。

保存先の例:

- `docs/ChatGPT議事録/東京/店舗名/機種名_Webアプリバックテスト_YYYYMMDD.md`

最低限、次を記録する。

- 店舗名
- 機種名
- 確認日
- Webアプリで指定した期間
- 採用条件名
- 集計数
- 勝率
- 合計差枚
- 合計G数
- BB率
- RB率
- 合成
- ブドウ
- 機械割
- 平均設定
- ChatGPT回答内の該当バックテスト結果
- 差分
- 判定

## 照合する項目

少なくとも次を照合する。

- 採用条件名
- 採用条件の中身
- 対象期間
- 集計件数
- 合計G数
- BB率
- RB率
- 合成
- 合計差枚
- 平均差枚
- 勝率
- 機械割

件数だけを合わせてはいけない。件数が合っていても、RB、合成、差枚、機械割が大きく違う場合は未完了扱いにする。

## ずれがある場合

ChatGPT回答とWebアプリ実測値が大きくずれる場合は、完了報告をしない。

次を順に確認する。

- 予測日と実績日のずれ
- 最新日除外の有無
- 履歴不足日の除外
- 台番変更後の履歴リセット
- 機種名の統合や分離
- 採用条件名と実際の条件式の不一致
- 1位、上位2位、点数以上、次点差、危険条件などの扱い
- イベント日と通常日の分岐有無
- 当日前に分からない列を点数に使っていないか
- ブドウ、設定、狙度、次差などを実戦用説明変数に使っていないか

原因を特定し、必要なら実装を修正してから再度Webアプリでバックテストする。

## 照合台帳

すり合わせ状況は台帳に残す。

保存先の例:

- `docs/バックテスト照合/東京_ネオアイムジャグラーEX_照合台帳.md`

台帳には次を残す。

- 地域
- 店舗名
- 機種名
- ChatGPT回答ログの有無
- Webアプリ実測ログの有無
- 照合状態
- 主な差分
- 最終確認日
- 最終コミット

照合状態は、以下のように分ける。

- 未着手
- 原文取得済み
- Web実測保存済み
- 要修正
- 照合済み

## 完了条件

次を満たすまで完了扱いにしない。

- ChatGPT回答原文を保存している、または未取得であることが明確になっている
- Webアプリ実測バックテスト結果を保存している
- ChatGPT回答内のバックテスト結果とWebアプリ実測値を照合している
- ずれがある場合は原因を説明している
- 必要な修正を行い、再度バックテストしている
- 照合台帳を更新している
- コミットとpushが完了している
