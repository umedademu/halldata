# 台データオンラインAT補完仕様

## 対象

- 台データオンラインへ振り替えている店舗だけを対象とする。
  - ビームヒカリ
  - ワンダーランド須恵店
  - ワンダーランド南ヶ丘店
- `サイトセブン取得機種` でONにした機種だけを対象とする。OFFの機種は本体確認、台番別詳細、AT補完のいずれも開かない。
- 貸し出し単価が15円以上25円以下の、20円相当スロットだけを対象とする。
- 5円、5.6円などの低貸しスロットは対象外とする。
- ジャグラー系はAT補完の対象外とする。

## 取得経路

- GUIから台データオンライン取得を手動実行した場合は、選択済みの20円相当の非ジャグラー機種について、機種別一覧のG数、BB、RBと、台番別詳細の週間当たりグラフにあるATを取得する。
- 通常のみんレポ取得またはその定期取得が成功した場合も、対象店舗に限り、その後で選択済み機種のATだけを台データオンラインから補完する。
- みんレポ取得後のAT補完が失敗しても、先に保存できたみんレポ本体は失敗扱いにしない。失敗内容は保存結果の注意事項へ残す。
- 台データオンラインのページ移動は並列化せず、既存と同じ2秒から4秒のゆらぎ待ちを毎回挟む。

## 日付

- 週間当たりグラフに実際に表示された日付ラベルを読み、位置ではなく日付と台番で結合する。
- 取得上限は当日を含む直近8日とする。
- 8日より前に取り逃したATは、台データオンラインからは復元できないものとして扱う。

## 店舗・機種ごとの判定

判定は、店舗ID、基準へ寄せた機種名、20円相当の貸し出し区分の組み合わせで記憶する。保存先は `local_data/daidata_online_at_counter_rules.json` とする。

| 週間グラフの使用状況 | 判定 | Webでの扱い |
| --- | --- | --- |
| BBは未使用、RBとATを使用 | `at_to_bb` | ATをBBへ加算 |
| RBは未使用、BBとATを使用 | `at_to_rb` | ATをRBへ加算 |
| BB、RB、ATをすべて使用 | `ignore_three_counters` | ATを加算しない |
| BBとRBが未使用、ATを使用 | `at_to_bb` | 空いているBBを優先してATを加算 |
| AT系列なし | `no_at` | AT詳細を次回以降省略 |
| 判定材料不足 | `unknown` | ATを加算せず、次回も判定を試みる |

- `ignore_three_counters` は判定を記憶するが、後から方針を変えられるよう生のAT取得は継続する。
- 後日、まれな当たりによって判定が変わった場合は、その店舗・機種の保存済みAT行にも最新判定を適用する。生の回数は変更しない。
- 判定をやり直したい場合は、GUIを停止した状態で上記の判定ファイルから対象項目を削除する。

## 保存と優先順位

次の項目をBB、RBとは分離して保存する。

- `at_count`
- `at_display_slot`
- `at_source`
- `at_fetched_at`

`at_count` の欠損と0は区別する。取得できなかった値を0として補わない。

同じ日付と台番にみんレポと台データオンラインがある場合は、G数、差枚、生のBB、生のRBなどの本体値は従来どおりみんレポを優先する。ただし、台データオンラインのAT4項目だけは残す。保存順が逆でも同じ結果になるよう項目単位で結合する。

既存のSupabase表にはAT専用列を追加せず、AT4項目はR2、ローカル保存、Web表示用データへ保持する。

## Web表示と計算

- `at_display_slot=bb` の場合だけ、計算用BBを `生BB + AT` とする。
- `at_display_slot=rb` の場合だけ、計算用RBを `生RB + AT` とする。
- `ignore`、`unknown`、AT欠損では、生のBB、RBをそのまま使う。
- BB率、RB率、合成、設定推定、狙い度ランキング、ビームヒカリ1.0Sの前2営業日ボーナス合計、バックテストの実績集計には計算用BB、RBを使う。
- 生のBB、RB、ATは内部に残し、同じデータへ計算用回数を繰り返し適用してもATを二重加算しない。
