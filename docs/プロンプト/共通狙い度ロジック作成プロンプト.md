# 共通狙い度ロジック作成プロンプト

これらは、パチスロ店における店舗の各機種の過去データと、各機種のCSVを1つずつ渡して高設定投入のクセを1機種ずつChatGPTに分析させた際の回答内容になります。

単機種での分析だけだとカーブフィッティングのリスクがあるので、これらの全データおよび全分析結果を参考に、全機種に共通するロジックを考えてください。

目的は、店舗単位で共通して使える「共通狙い度」を100点満点で評価する計算式と、実戦で採用するための「共通採用条件」を作ることです。

このプロンプトは、単機種ロジック生成用プロンプトを別ファイルとして添付しない前提で作っています。このプロンプト単体で、共通ロジック生成に必要な前提をすべて満たすものとして扱ってください。

## 入力として渡すもの

- 対象店舗の主要10機種分のCSV
- 各機種を単体で分析したChatGPT回答または議事録
- 店舗や日付に関する議事録
- イベント日、通常日、対象期間などの補足情報

各機種につき、原則として「CSV」と「単機種分析の回答または議事録」が1つずつあります。まず、どの機種にどのCSVと議事録が対応しているかを確認してください。不足、重複、対応不明のファイルがある場合は、分析を始める前に明記してください。

## 最重要方針

- 単機種だけで強く見えるクセは、共通ロジックに入れすぎないでください。
- 複数機種で同じ方向に再現しているクセを優先してください。
- クセの例はあくまで仮説です。無理に採用せず、根拠が弱いものは不採用または参考扱いにしてください。
- 条件を細かくしすぎて、過去データだけに合ったロジックにならないようにしてください。
- 件数が少ない条件は、通常採用ではなく参考扱いにしてください。
- 機種名や固定台番そのものを直接優遇する条件は作らないでください。
- 予測対象日の当日結果として初めて分かる差枚、G数、BB、RB、合成、ブドウ、設定、機械割などは、狙い度の入力に使わないでください。
- 既に計算済みの狙い度、順位差、次点差など、出力側の値を入力条件として使わないでください。
- 必ず通常日用とイベント日用で分けるべきかを検討してください。分ける必要がない場合は、その理由も書いてください。
- 全機種を同じ判定指標で評価しないでください。ジャグラー系とAT機、スマスロ系では、高内容判定に使える情報の信頼度が違います。

## 機種タイプ別の高内容判定

共通ロジックを作る前に、機種タイプごとに高内容の判定基準を分けてください。

### ジャグラー系

ジャグラー系は、CSVから設定判別に使える情報が比較的多いため、以下の優先順で高内容を判断してください。

- 最優先: RB率
- 次点: ボーナス確率、合成確率
- 補助: 機械割、差枚

優先順位は、原則として以下です。

- RB率 ＞ ボーナス確率、合成確率 ＞ 機械割、差枚

差枚や機械割だけが強い台を、RB率が弱いにもかかわらず強い高内容として扱いすぎないでください。

### AT機、スマスロ系

カバネリ、モンキーターンなどのAT機やスマスロ系は、CSV上のボーナス確率だけで設定判別するのが難しいため、以下の優先順で高内容を判断してください。

- 最優先: 機械割、差枚
- 補助: G数、勝率、安定してプラスになっているか
- 参考以下: ボーナス確率

優先順位は、原則として以下です。

- 機械割、差枚 ＞＞＞＞ ボーナス確率

AT機やスマスロ系では、ボーナス確率を強い設定判別材料として扱わないでください。

### 共通化する時の考え方

- まず機種タイプごとに「高内容だったか」を判定してください。
- そのうえで、前回高内容からの日数、凹み後の扱い、据え置き傾向、連続投入、冷却期間など、機種タイプをまたいで比較できる要素を共通ロジック化してください。
- ジャグラー系のRB率とAT機のボーナス確率を、同じ重みで直接比較しないでください。
- ジャグラー系の高内容とAT機の高内容は、判定材料は違っても、共通ロジック上では「その機種タイプ内で強い内容だった日」として扱ってください。

## 検証してほしい店のクセの例

以下は、検証してほしい代表的な仮説です。該当しないものは不採用にしてください。

- 直近で高設定が入っていない台を順番に使う傾向
- 長期間高設定が入っていない台への救済傾向
- 前日、2日前、3日前など直近で大きく凹んだ台への上げ傾向
- 逆に、大きく凹んだ台を避ける傾向
- 前日高内容だったが不発だった台の据え置き傾向
- 前日高内容でしっかり出た台の据え置き傾向
- 高設定投入後、翌日すぐ落とす傾向
- 高設定投入後、数日は同じ台を避ける冷却期間の傾向
- 同じ台に2連続、3連続で入れる傾向
- 連続投入はするが、一定回数で止まる傾向
- 直近でよく出ている台をさらに使う傾向
- 直近で出すぎた台を避ける傾向
- 稼働が少ない台を救済的に使う傾向
- 稼働が少ない台を判断材料不足として避ける傾向
- 稼働が多い台を優先して使う傾向
- ボーナス回数、RB、合成確率などが弱かった台を上げる傾向
- RBだけ強かった台を据え置く傾向
- 差枚は弱いが中身が良さそうな台を据え置く傾向
- 差枚は強いが中身が弱そうな台を落とす傾向
- 同一機種内で1位、2位、3位など順位上位に来る台の共通条件
- 1位と2位の点差が大きい台を重視する傾向
- 上位候補が横並びの日は見送るべき傾向
- 通常日とイベント日で投入傾向が変わる傾向
- イベント日は素直に強い台を使うが、通常日はズラす傾向
- 特定曜日だけ出し方が変わる傾向
- 月初、月末、給料日前後など時期で変わる傾向
- 機種をまたいで、前回強かった台の翌日扱いが共通しているか
- 機種をまたいで、凹み台の扱いが共通しているか
- 機種をまたいで、据え置きの強さが共通しているか
- 機種をまたいで、長期放置台の扱いが共通しているか
- 機種をまたいで、稼働不足台の扱いが共通しているか

## 作成してほしいもの

### 0. 入力ファイル確認と機種別要約

最初に、入力されたファイルを機種ごとに整理してください。

以下を表でまとめてください。

- 機種名
- CSVファイル名
- 議事録または単機種分析ファイル名
- 機種タイプ
- 高内容判定で最優先する指標
- CSVから見える主な事実
- 議事録で提案されている主なクセ
- 共通ロジックに使えそうか

機種タイプは、少なくとも以下に分けてください。

- ジャグラー系
- AT機、スマスロ系
- その他

この機種別要約を出したうえで、全機種に共通するクセを抽出してください。

### 1. 共通狙い度の100点満点計算式

全機種に共通して使う点数式を作ってください。

以下を必ず含めてください。

- 使用する変数の一覧
- 各変数の意味
- 点数の加点、減点、上限、下限
- 100点満点へ丸める方法
- 通常日とイベント日を分ける場合の計算式
- 機種タイプ別の高内容判定
- 履歴不足台をどう扱うか
- 店休日、欠損日、全台G数0の日をどう扱うか
- 台番変更、増台、減台、島変更があった場合に履歴をどう扱うか

### 2. 共通採用条件

点数式とは別に、実戦で採用するための共通採用条件を作ってください。

以下の4分類で整理してください。

- 通常採用
- 弱め採用
- 参考表示
- 見送り

採用条件には、以下のような観点を含めてください。

- 共通狙い度が一定以上
- 同一機種内で1位、または上位数台
- 2位以下との点差が一定以上
- 複数の共通根拠が重なっている
- 単機種だけで強い根拠ではなく、複数機種で再現している
- 危険条件に該当していない
- 見送り条件に該当していない
- 通常日用とイベント日用で条件を分ける必要があるか
- 上位候補が横並びの日を見送るべきか

### 3. 危険条件と見送り条件

以下を分けて作ってください。

- 点数を下げる危険条件
- 採用対象から外す見送り条件
- 参考表示に落とす条件

特に、以下を検証してください。

- 連続投入の上限に達している台
- 出すぎた直後で落とされやすい台
- 履歴不足で根拠が薄い台
- 単機種だけでは強いが、全機種では再現しない条件
- 件数が少なすぎる条件
- 上位候補同士の差が小さすぎる日

### 4. 単機種ロジックとの使い分け

単機種ロジックと共通ロジックの関係を整理してください。

以下を必ず提案してください。

- 共通ロジックだけで採用してよい場面
- 単機種ロジックを優先すべき場面
- 両方が強い時に最優先する条件
- 単機種ロジックは強いが、共通ロジックが弱い時の扱い
- 共通ロジックは強いが、単機種ロジックが弱い時の扱い
- 最終的な狙い度ランキングで、共通点数をどの程度反映するべきか

### 5. バックテスト結果

以下の単位でバックテストしてください。

- 全機種合算
- 機種別
- 通常日
- イベント日
- 前半期間
- 後半期間
- 月別
- 共通採用条件別
- 通常採用、弱め採用、参考表示、見送り別

各結果には、少なくとも以下を出してください。

- 件数
- 勝率
- 合計差枚
- 平均差枚
- 合計G数
- BB率
- RB率
- 合成確率
- 機械割
- 平均設定

結果を評価する際は、ジャグラー系ではRB率と合成確率を重視し、AT機やスマスロ系では機械割と差枚を重視してください。全機種合算では、機種タイプごとの判定材料の違いを考慮したうえで評価してください。

## 過剰な当てはめ対策

以下を必ず確認してください。

- 前半期間だけ強く、後半期間で崩れていないか
- 一部の月だけに偏っていないか
- 一部の機種だけに偏っていないか
- 件数が少なすぎないか
- 条件が細かすぎないか
- 勝率だけでなく、差枚、RB、合成、機械割でも裏付けがあるか
- 不採用にしたクセと、その理由を明記しているか

## 回答形式

回答は以下の順番で書いてください。

1. 入力ファイル確認
2. 結論
3. 機種別要約
4. 全機種に共通していると判断したクセ
5. 共通とは言い切れないため不採用または参考扱いにしたクセ
6. 機種タイプ別の高内容判定
7. 共通狙い度100点満点の計算式
8. 共通採用条件
9. 危険条件と見送り条件
10. 単機種ロジックとの使い分け
11. バックテスト結果
12. 過剰な当てはめ対策の確認結果
13. Webアプリへ実装するための条件式まとめ

最後に、Webアプリへ実装するための正本として、条件名、条件式、点数、上限、下限、採用区分を表でまとめてください。
